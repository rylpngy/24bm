# 阶段十二客户演示问题清单与下一阶段产品路线拆分

生成时间：2026-06-21T14:31:00Z

## 决策结论

阶段十二三端演示已经完成总收口，当前基线证据是 `docs/stage-twelve-three-role-demo-closeout-package.md`：采购方主流程、供应商协同、平台运营均已有独立演示入口、收口文档和真实动作证据，合计 17 个真实动作。

下一步不应同时启动所有路线，而应先把客户演示问题沉淀成结构化清单，再按反馈选择一个下一阶段业务域进入可演示切片。推荐下一步：客户演示问题清单模板先落地，随后按反馈选择一个下一阶段业务域。若没有演示阻断，推荐优先进入合同深化或财务深化二选一。

## 反馈分类处理规则

| 反馈分类 | 判定标准 | 处理动作 | 验收证据 |
| --- | --- | --- | --- |
| 演示阻断 | 页面无法访问、加载失败、按钮缺失、关键动作无法完成 | 暂停新功能，立即修复 | 单项测试、浏览器验收、无加载失败和真实动作恢复 |
| 业务理解问题 | 客户不理解流程边界，但当前功能可以解释 | 补页面提示、讲解稿、FAQ 或演示顺序 | 文档测试、UI 文案测试、演示话术更新 |
| 生产化缺口 | 关系到上线、安全、权限、审计、运维、接口、数据治理 | 进入生产级治理路线，拆成非演示型验收项 | 权限矩阵、接口清单、部署运维清单、审计测试 |
| 下一业务域扩展 | 客户明确提出新业务主线，且有角色、对象、状态流转 | 进入下一阶段路线表，选择一个最小可演示切片 | 页面入口、真实动作、验收文档、暂不声明范围 |
| 暂缓需求 | 只有方向，没有业务规则、数据样本或接口边界 | 进入需求池，不进入当前研发 | 需求池记录、暂缓原因、再次触发条件 |

## 下一阶段产品路线拆分

阶段十二之后的纪律是：不同时启动商城直采、竞价采购、合同深化、财务深化、平台生态和生产级治理。每次只进入一个业务域，先做可演示切片，再决定是否继续生产化。

| 业务域 | 推荐优先级 | 适合进入条件 | 第一轮演示目标 | 暂缓原因 | 验收证据 |
| --- | --- | --- | --- | --- | --- |
| 合同深化 | P1 | 客户关注订单之后的合同台账、审批、履约事件和归档 | 从采购订单生成合同，演示合同审批、履约事件、关联合同和归档边界 | 若客户还停留在询价比价验证，合同可后置 | 合同页面入口、合同真实动作、合同收口文档 |
| 财务深化 | P1 | 客户关注三单匹配、付款申请、付款批次、冻结原因和归档异常 | 演示三单匹配、付款申请、付款批次和异常处理入口 | 若客户只验证采购主流程，复杂财务可后置 | 财务页面入口、付款真实动作、财务验收文档 |
| 商城直采 | P2 | 客户有常采目录、协议价、快速下单和供应商商品维护场景 | 商品目录、协议价、购物车、快速下单演示雏形 | 会引入商品主数据和价格体系，容易稀释询价比价主线 | 商城页面入口、下单动作、商品样本 |
| 竞价采购 | P2 | 客户明确需要多供应商实时出价、排名和截标 | 竞价规则、轮次、出价排名、截标结果 | 规则和交互复杂，需先明确公平性和审计口径 | 竞价页面入口、出价动作、截标结果 |
| 平台生态 | P2 | 客户关注公共供应商市场、品类能力、供应商推荐和平台运营 | 公共供应商市场、品类标签、供应商推荐候选 | 需要更多供应商主数据和评价数据支撑 | 平台市场入口、推荐说明、运营指标 |
| 生产级治理 | 条件触发 | 客户进入上线谈判或试点部署 | 权限矩阵、审计日志、安全、备份、部署和接口清单 | 如果仍是演示验证，过早投入会拖慢业务域迭代 | 生产验收清单、运维文档、安全测试 |

## 推荐下一步可执行切片

推荐下一步：客户演示问题清单模板先落地，随后按反馈选择一个下一阶段业务域。

若没有演示阻断，推荐优先进入合同深化或财务深化二选一：

- 合同深化适合承接采购订单之后的管理诉求，能够延伸“订单 -> 合同 -> 履约 -> 归档”。
- 财务深化适合承接发票付款之后的上线诉求，能够延伸“三单匹配 -> 付款申请 -> 付款批次 -> 异常归档”。

每次只进入一个业务域。进入后必须明确：

- 页面入口
- 真实动作
- Java 数据源
- 验收文档
- 暂不声明范围

## 下一阶段进入条件

| 条件 | 是否必须 | 说明 |
| --- | --- | --- |
| 三端演示总收口包通过 | 必须 | 以 `docs/stage-twelve-three-role-demo-closeout-package.md` 为基线 |
| 演示阻断清零 | 必须 | 有阻断先修复，不进入新业务域 |
| 业务域只选一个 | 必须 | 防止同时启动商城、竞价、合同、财务、平台生态 |
| 第一轮只做可演示切片 | 必须 | 不直接承诺生产上线闭环 |
| 有真实动作或明确可点击入口 | 必须 | 保持产品可演示优先 |

## 暂缓说明

- 商城直采、竞价采购、复杂招标和 AI 暂不同时启动。
- 真实支付、税控开票、电子签章暂不进入下一轮。
- ERP/OA/财务系统深度集成需先有接口清单和责任边界。
- 生产级治理只有在客户进入上线或试点部署时才整体启动。
