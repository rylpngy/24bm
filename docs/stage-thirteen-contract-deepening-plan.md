# 阶段十三计划：合同深化可演示切片

生成时间：2026-06-21T14:34:00Z

## 阶段定位

阶段十三从 `docs/stage-twelve-customer-demo-feedback-roadmap.md` 承接而来。阶段十二已经完成三端演示总收口，并建议在没有演示阻断时，从合同深化或财务深化中选择一个下一阶段业务域进入可演示切片。

本阶段选择合同深化，但不是从零重做合同系统。阶段十已经证明合同管理可以承接采购订单，证据包括 `docs/stage-ten-contract-closeout-review.md`、`docs/stage-ten-contract-demo-path-review.md` 和 `docs/artifacts/stage-ten-contract-demo-path-result.json`。阶段十三第一轮的目标是把合同管理从“阶段十可讲通”推进到“下一阶段客户演示可单独验证”，补齐合同总览、合同审批、履约事件、订单/收货/发票/付款关系和归档门禁的演示验收口径。

## 第一轮 MVP

阶段十三第一轮 MVP 是合同深化可演示切片，不从零重做合同系统。

必做：

1. 合同总览：合同管理页首屏能快速说明合同数量、待审批、履约中、可归档和风险提示。
2. 合同审批：明确提交合同审批、审批中心承接、审批通过后合同状态回写的演示路径。
3. 履约事件：合同详情能说明收货、发票、付款和履约备注如何沉淀为履约事件。
4. 订单/收货/发票/付款关系：合同详情继续聚合订单、收货、发票和付款状态，讲清合同不直接替代这些业务模块。
5. 归档门禁：归档合同必须说明前置条件、不可归档原因和归档后的只读边界。
6. 演示操作条：合同页第一屏提供“本页讲什么、能点什么、点完去哪、为什么不能点”的操作提示。
7. 推荐合同样本：保留并强化推荐合同样本，避免现场临时找数据。

第一轮暂不做：

- 电子签章、真实盖章、印章管理。
- 法务红线批注、合同版本对比、条款结构化审查。
- 外部合同系统、对象存储、签章平台或法务审批系统集成。
- 合同自动驱动订单、收货、发票或付款状态。
- 真实支付、税控开票或银企直连。
- ERP/OA/财务系统深度集成。

## 演示路径

推荐阶段十三第一轮演示顺序：

1. 从采购订单进入合同管理，说明合同来源于已生成采购订单。
2. 在合同管理页查看合同总览、推荐合同样本和演示操作条。
3. 进入合同详情，讲合同审批、履约事件、订单/收货/发票/付款关系和归档门禁。
4. 提交合同审批后进入审批中心，说明合同审批与需求审批、定标审批共用审批中心。
5. 从合同详情跳转收货验收和发票付款，说明合同只聚合关系，不替代业务动作。
6. 回到合同详情说明归档条件和不可归档边界。

## 验收口径

阶段十三第一轮必须具备以下验收证据：

- 页面入口：`http://localhost:3000/?role=buyer&module=contracts`
- 真实动作：提交合同审批、推进履约、处理收货验收、处理发票付款、归档合同。
- Java 数据源：合同页和关联审批、收货、发票付款页面均使用 Java 数据源作为主验收路径。
- 验收文档：输出阶段十三合同深化 UI 和真实动作复验结果。
- 浏览器视觉验收：覆盖合同管理页桌面 1280x720 和移动 390x844，检查无加载失败、无 `argument type mismatch`、无 React runtime error、无整页横向溢出。
- 自动测试：`npm test` 覆盖阶段十三合同计划、合同 UI 提示、合同真实动作复验和收口包。
- 构建验证：`npm run build` 通过。
- 后端回归：如触碰 Java 合同接口或数据库，运行 `mvn -q test`。
