# 实物退货、换货与退款清算

## 业务入口

- 采购方：采购订单详情 → 售后记录 → 实物交接与凭证。
- 供应商：商城售后办理 → 实物交接与凭证。
- 退货财务处理：对应订单 → 合同解除与订单清算。

## 操作顺序

1. 买方按订单行申请退货或换货，供应商受理。
2. 买方登记寄回数量、物流编号、说明及凭证原件。
3. 供应商核对实物并登记签收凭证。
4. 换货由供应商补发，买方登记合格或不合格复验。不合格时重新办理寄回、签收、补发、复验，不允许直接关闭责任。
5. 实物证据齐全后供应商提交处理结果，买方确认。
6. 退货继续在订单清算中核对实际保留数量、双方协议、独立审批、退款到账和最终发票/红冲凭证；只有实际净付款与清算额一致，才能完成。
7. 采购执行和项目归档纳入全部售后历史、交接台账及双方上传的原件，ZIP 中保留 SHA256 校验清单。

## 控制边界

- 原订单、合同、原收货、发票和付款流水不覆盖。退款通过独立清算流水核算，预算仍保留预警模式；项目关闭前不提前释放需求责任。
- 单张售后单交接全量核验；分批处理应拆分售后单。累计申请数量不得超过订单数量，交接还须核对实际收货量。
- 换货限同数量、同价责任履行，不新增应付款。升级型号、价差、额外采购需另行办理采购及合同变更。
- 退回货物不自动增加可售库存，避免把未质检退件当作新品。既有清算仅按已知未发货预留量释放库存。
- 每次交接要求真实凭证原件（单文件最大 2MB），记录办理人、岗位、时间和内容摘要；原件不可修改或删除。只允许当前企业/订单数据范围内的买方或本供应商访问。
- 历史“已完成”不推定实物核验完成，可以补录真实交接证据；正在清算、已归档或已终止清算的订单禁止新增实物责任。
- 本轮退款为真实到账凭证登记及核对，不连接银行划款或税控红冲。退货财务复用既有单合同、单发票清算边界，多发票分摊及历史付款不明继续提示人工核对，不按零推算。

## 验收方法

- PostgreSQL 集成测试覆盖退货后保留净额、退款、预算、库存不重复回补；换货不合格重办；租户/供应商边界；幂等提交；历史补证及凭证不可变。
- 隔离数据库 HTTP 验收启用 `PROJECT_PHYSICAL_AFTER_SALES_ACCEPTANCE=1`，结合项目分包、商城和合同清算验收运行，不向原系统写入测试数据。
- 浏览器验证采购方和供应商实际操作、原件下载及桌面/移动展示；发布前先备份原数据库和附件，迁移副本验证通过后才更新原系统。
