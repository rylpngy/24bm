## 1. 版本范围冻结

本版本纳入质量整改第1至16轮的运行代码、针对性测试、接口契约、数据库迁移、CI门禁和核查工具。包括账号会话失效、权限及数据范围、需求分页与编号、统一工作流策略、付款金额与审批约束、附件完整性、供应商公私域隔离、供应商默认角色、跨端链路修复。

鲁东业务本轮仅随公共接口适配上传票据及工作流业务策略声明，不增加新的学校业务需求。现有POC功能不作为本次新交付功能重复计算。

不纳入客户PPT/Word/报价附件、文档生成脚本、渲染图、临时目录、运行数据和密钥。不删除这些本地文件。逐文件提交候选清单及内容摘要见 `quality-hardening-release-manifest.json`。

本版本不承诺：新采购方式、新UI改版、生产真实支付、第三方供应链/学校SSO已联调、全部复杂审批与分批履约覆盖、生产容量及容灾全部达标。后续非阻断性优化另列任务，不继续扩大当前版本。

## 3. 迁移清单

先核对目标 `flyway_schema_history`、`flyway_seed_history` 及真实版本，禁止通过repair、改历史checksum或清库绕过冲突。

| 版本 | 变更 | 上线注意事项 |
| --- | --- | --- |
| V203 | 需求编号序列 | 取号接续存量最大编号；导入需求需核对编号，不直接绕过分配器 |
| V204 | 会话版本与触发器 | 停用和改密码使旧本地令牌失效；准备重新登录通知，不代表完成IdP全局登出 |
| V205 | 上传票据 | 前后端需一起升级，旧客户端上传方式不可单独保留 |
| V206 | 付款金额流水及合同分配 | 不从历史“已付款”状态伪造金额流水或期初余额 |
| V207 | 历史付款核对记录 | 记录依据不等于入账、付款或审批通过 |
| V208 | 附件大小及哈希 | 新附件建立基线；旧附件不自动补可信基线，路径异常须核实归属 |
| V209 | 供应商私域资料 | 核对公共与私域字段；不能覆盖其他企业共享主档 |
| V210 | 明确供应商管理员、业务成员角色 | 不自动替换旧角色；历史“销售”可能仍为管理员，必须确认 |

除上述迁移，Flowable可能更新其自身表结构；预发布必须核对引擎版本及启动行为，不只检查Flyway版本。不要对生产库先试启动再决定是否升级。

## 4. 部署实施顺序

1. 确认发布提交SHA、四端部署范围、目标服务器、数据库、对象存储桶、认证方案、维护窗口及责任人。当前本机验收库25432/quality_hardening不作为正式业务库。
2. 停写或采用已验证的一致性备份机制；成组备份数据库、附件对象、必要配置及密钥。备份存入受控持久位置，不依赖 `/tmp`；先在独立恢复环境验证可登录、可读取业务及附件。
3. 以目标数据副本做预发布迁移，禁止加载验收租户及测试账号。使用 `scripts/data-audit.mjs` 只读核查，凭真实业务材料处理异常，未经确认不批量改权限、付款或附件引用。
4. Java21构建后端并以不可变JAR副本或镜像运行；前端使用锁定依赖构建四端。构建与运行分离，避免覆盖运行中的JAR。记录版本及产物SHA256。
5. 配置HTTPS和反向代理，四端指向同一确认后的API；避免默认沿用本地开发代理。数据库、对象存储管理端和内部API不直接暴露公网。检查CORS、代理上传限制及超时。
6. 先验后切：健康检查、平台/采购/供应商真实岗位登录、受限岗位拒绝操作、需求及附件、订单履约、付款审批与登记、审计身份。由业务方确认后才切换正式入口。
7. 观察错误日志、审批待办、接口延迟和备份结果，记录验收结论及遗留清单。出现阻断问题按回退方案处理，不用改库状态强行验收。

### 必须显式确认的配置

- `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`：目标库，不得沿用默认共享库。口令经受控配置注入，不提交Git。
- `APP_SEED_LOCATIONS`：正式部署为空；本地profile默认可能加载db/dev，不能不检查直接使用local profile。新库初始化组织和账号必须有单独受控方案，空种子不等于业务已初始化。
- `JWT_SECRET`、`ALLOW_DEMO_JWT_SECRET=false`、`TENANT_HEADER_FALLBACK_ENABLED=false`：禁止演示签名和信任请求头的旧模式。
- `SELF_LOGIN_ENABLED`、`KEYCLOAK_ENABLED`及JWKS：按真实认证方案配套确认，不得在未完成SSO联调时直接关闭唯一可用登录途径。
- `MINIO_ENDPOINT`、访问凭据、`MINIO_BUCKET`：正式桶与验收桶分离；核对附件迁移与读取权限。
- `CORS_ALLOWED_ORIGINS`、服务端口、监控端点访问控制：按目标域名设置，不直接暴露详细健康信息及管理指标。
- 四端仍引用外部字体服务：内网发布前改为经确认的本地字体或系统回退，本轮记录为发布环境检查项，不将Google字体成功连接作为业务前置条件。

main中的 `.mise` 和 `infra/ludong-poc-prod` 面向鲁东POC，其固定入口和单门户打包方式不能视为四端原系统部署方案。尤其不得运行其中清理POC数据的命令来准备本版本。

## 5. 回退方案

先保留上一版前后端不可变产物及版本标识。前后端、数据库、附件、认证配置作为一组评估，不能只换前端来掩盖接口不兼容。

- 尚未发生数据迁移且无新增写入：确认兼容后恢复上一版产物和代理配置，检查登录、接口和附件。
- 已迁移数据库或产生新业务写入：立即停止写入，先保全新增数据和日志，评估修复或恢复。需恢复时使用迁移前成组备份到独立环境验证，明确维护窗口之后新增数据的保留与补录办法，再经批准切换。
- 不使用Flyway repair、删表、手工降版本或数据库清空作为回退。旧代码与新表结构未经验证不得直接混跑。
- 原POC和其他环境独立，不随本版本回退；生产部署、数据删除及恢复覆盖须单独确认。

## 6. 业务验收清单

- 平台：企业开通、采购及供应商管理员能够登录；普通供应商成员不能管理团队。
- 采购：需求创建、审批、询价、定标及订单；跨租户、部门受限数据不可越权查看或修改。
- 供应商：报价、确认订单、发货、开票；零税率保留，错误提交明确提示。
- 财务：收货及发票匹配、付款申请和批次审批、金额登记、重复操作限制、买卖双方状态一致；真实资金支付另验。
- 工作流：办理人、历史、业务状态同步；鲁东扩展上传和同工号复用保持已有兼容，不修改客户业务规则。
- 附件：上传、核验、下载、拒绝跨租户访问；历史异常明确提示。
- 运维：版本身份、日志、备份恢复、异常及回退演练记录齐备。
