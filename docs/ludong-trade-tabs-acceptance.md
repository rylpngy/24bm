# 订单、验收及发票付款分栏验收

日期：2026-10-28

## 页面调整

| 页面 | 分类 | 保留能力 |
| --- | --- | --- |
| 采购订单详情 | 基本信息、采购明细、发货物流、收货验收、取消与清算 | 原有列表、到货信息、履约记录及取消条件校验 |
| 收货登记 | 订单与批次、数量核对、质检处置 | 累计数量校验、部分收货、质检及原提交参数 |
| 历史验收详情 | 基本信息、验收明细、质检与处置、关联批次 | 独立详情、返回原列表、处置复核入口 |
| 发票付款详情 | 基本信息、三单匹配、差异处理、付款登记、执行记录、审批记录 | 行级对账、差异处理、付款申请、金额登记、冲销及批次工作台 |

切换 TAB 不清空当前记录已输入的验收、差异或付款表单。此处仅保证页面内切换保留，不代表新增服务端草稿保存能力。

付款审批记录改用发票关联的真实付款申请 ID 查询，并展示其付款批次审批历史，不再误用发票 ID 查询付款申请流程。

关联批次显示同一订单的发货记录，不推断验收记录与某个发货批次的一一对应关系。

## 验证结果

- 前端类型检查通过；采购方门户生产构建通过。
- 8 个针对性测试文件、33 项测试通过，覆盖 TAB 分类、输入保留、付款审批标识、付款参数、部分收货、权限、处置复核和差异处理。
- 独立 POC `5288` 桌面视口 `1280×720`：实际订单的 5 个 TAB、历史验收的 4 个 TAB、发票的 6 个 TAB 均已点击核验。
- 实际数据核验：两项设备、发货及验收数量 5、发票金额 178000 元、累计已付 53400 元、剩余应付 124600 元；付款申请及批次均显示已通过及完整流转记录。
- 验收详情返回后仍停留在验收记录列表。已检查的验收列表和发票页面无整页横向溢出；浏览器错误日志为空。
- 本轮未进行付款、冲销、取消、验收等业务写入。前后通过 GET 读取并逐字段比较订单、发货、收货、发票、合同五类数据，完全一致。

## 验证边界

- 当前演示订单已经全部收货，新增收货登记的输入保留、部分收货与权限由测试覆盖，本轮没有为浏览器验收新增或改写业务记录。
- 未补跑移动端视觉验收，不将桌面结果表述为移动端通过。
- 无 Java、数据库或迁移变更，未运行 Java 回归；未修改原系统 `5173/8080` 服务及其数据库。
- 页面组件属于公共采购方门户，独立 POC 继续复用；本轮预览在 `5288`，不等同于原系统重新发布。
