# 项目分包与商城、竞价采购贯通说明

## 使用入口

采购方 → 项目库 → 已批准项目详情 → 采购分包 → 分包详情。先建立分包并生成或关联采购需求，需求须完成独立审批。

本批继续采用一个分包对应一个有效采购执行。商城、竞价沿用现有采购来源及履约体系，不建立另一套订单、预算、收货或财务台账。

## 商城选型下单

具备项目管理、需求查看、商城查看/采购、询价来源查看/管理和订单管理权限时，可在尚未下发过执行的待采购包点击“商城选型下单”。

- 商城规格须已关联分包批准的采购目录物料，计量单位一致，采购方可见且在架。未关联、其他企业私域、下架、库存不足或不满足起订/步长的商品不能下单。
- 每项物料可分配多个SKU，但累计数量必须等于批准需求和分包数量；不能额外购买、少购或用其他物料代替。SKU不可重复，同SKU应合并数量。
- 一包由同一供应商履约；多供应商采购通过不同分包承接。普通商城独立购物车仍保留原有按供应商拆单能力，不把一包的完整需求重复关联给多家供应商。
- 服务端锁定商品后读取实际目录/阶梯价；页面目录价仅作选型参考。实际总额不能超过已批准需求预算及分包金额。此限制与部门预算预警模式相互独立，预警模式不等于可以超出已批准采购范围。
- 收货地址和期望到货日期沿用商城规则，日期不能早于承诺交期，企业采购限额、品类和地址要求仍生效。
- 确认后生成真实商城来源和订单，关联原批准需求及原部门年度预算；不再创建直录需求，不额外占用一份独立订单预算。
- 提交编号、请求内容和办理人用于防重复校验；同一次原样重试返回原订单，不重复扣库存，不接受换编号重复购买。异常会整体回滚来源、订单、库存、选型记录和相关预算处理。

已成交记录保留选型时的商品、品牌、型号、参数、数量、单价和金额，以及原批准快照、需求集合、下单依据、办理人与时间。后续目录价格/型号变化不改写历史成交记录。分包中可查看原记录并进入实际采购订单。

已下发过其他采购执行的包不能直接覆盖为商城下单；失败执行仍须遵守保留历史的重采边界，本批不提供将已有采购记录改名为商城的捷径。

## 竞价采购

在待采购包选择“竞价采购”，填写起拍总价、最小降价步长、开始/截止时间及自动延时设置，再填写办理原因并下发。

- 未填写起拍价时采用已批准需求预算与分包金额的较小值；不能高于该上限。降价步长不能超过起拍价。
- 自动延时默认采用现有竞价引擎5分钟触发/5分钟顺延规则，可在项目分包设置；窗口或时长设0时关闭，参数范围0至120分钟。
- 下发创建真正的竞价草稿，在原询价/竞价业务中完善邀请和报价要求并发布，不是只有“竞价”名称的普通询价单。
- 供应商初次报价和再次降价使用原有提交/更新路径；起拍价、当前最低价、降价步长、计划开场和截标时间继续由现有引擎校验。不能用普通询价的提前开报价动作绕过竞价截止时间。
- 定标仍需独立审批，后续生成实际订单并履约。已流标/废标、没有任何订单的执行可按原失败重采规则重新下发竞价，保留旧记录和原需求来源；同包不能同时存在两个有效采购执行。

## 汇总、履约与归档

商城和竞价来源在执行历史中展示真实采购方式，进入原订单确认、发货、收货与质量处置、合同、发票、付款登记和对账流程。

项目汇总按有效来源计算一次。六类进度仍取实际业务，分包与项目结项继续校验收货数量、质量、合同、有效发票、付款净额、差异和未完成审批。商城选型快照纳入原分包归档与整项目档案，来源与原件完整性重新核验，不用当前商品信息替代历史证据。

现有订单不能直接终止清算。净付款登记不等于外部银行支付；本批不新增第三方供应链、支付或客户系统的正式联网接入。

预计升级后182张表、135条迁移；最终结果以发布目录RESTORATION、构建哈希和CI/验收回执为准。验收业务不写入原系统，不导入验收租户替代原数据。
