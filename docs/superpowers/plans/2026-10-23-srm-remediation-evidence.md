# 整改佐证附件

沿既定SRM计划继续开发，用户已要求常规步骤无需重复确认。PR113保持原SHA等待单独合并确认，本批独立分支codex/srm-remediation-evidence，不更新原5173/8080。

## 实现边界

- 复用ObjectStorageService、认证下载与SHA-256核验；不复用仅允许采购租户的附件接口，避免供应商伪装租户。
- 供应商在待整改阶段上传，绑定任务、当前版本和整改轮次；每轮最多10份，每份最多10MiB。重试相同文件名/摘要返回原记录。
- 允许PDF、PNG、JPEG、DOCX、XLSX；全部作为附件下载，不内联执行。不承诺病毒扫描。
- 文件登记与提交反馈使用任务行锁串行化；已提交/关闭不可补传，不覆盖历史。不提供删除入口。
- 双端可读取已提交轮次，供应商可看本轮草稿；采购方在提交前不可见供应商草稿。
- 单独附件表记录原名、长度、摘要、上传人及时间；对象键随机且不对外返回。对象存储成功而数据库事务失败可能遗留不可访问对象，后续存储治理处理，不误报为已提交材料。

## 验证顺序

1. 数据库集成测试先失败，再实现权限、版本、轮次和下载核验。
2. 双端接入上传/下载列表、忙碌/错误状态；同步OpenAPI。
3. Java/前端回归、隔离HTTP及浏览器真实文件闭环；原服务只读健康检查。
4. 更新台账并独立提交，不覆盖PR113。

## 验证结果

- 760项Java单测、9项PostgreSQL绩效集成测试、56文件233项前端测试、七包类型检查、采购方与供应商预览构建通过；OpenAPI新增5个业务操作（4个路径），契约检查通过。
- 隔离8095新增V215；真实HTTP验证同文件重试去重、未提交材料采购方不可见、提交后冻结及认证下载。浏览器5197/5198完成第二轮上传、反馈、采购方下载并比对字节、复核关闭及390移动显示，无页面运行错误和整页横向溢出。
- 证据：/tmp/srm-evidence-fixture.json、/tmp/srm-evidence-browser.json、/tmp/srm-evidence-{buyer,supplier}[-mobile].png。HTTP和浏览器脚本保存在本机.tmp，不包含在代码交付；自动回归在PerformanceTaskIT、PerformanceEvidenceControllerTests及EvidencePanel测试中。
- 审查发现并修复：读取原始上传体时有界缓冲（最多10MiB+1），上传期间禁止关闭/切换任务和提交反馈，中文文件名采用filename*下载响应头；相关回归与真实浏览器已通过。
- 受限范围：不提供附件删除/替换，不含病毒扫描、外部长期档案服务或孤立对象自动清理。数据库失败后可能遗留不可访问对象；权限和摘要核验不等同于文件内容安全认证。并发场景主要依靠与现有提交相同的数据库任务行锁，本轮未额外做故障注入压力测试。
- 原5173/8080仍ec0cc1ed，原库未运行V215。依赖PR113的5965fa2c，本批提交不得混入尚待确认的PR113。
