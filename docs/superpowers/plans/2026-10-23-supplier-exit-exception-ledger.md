# 供应商退出异常逐笔核对

## 范围与取舍

沿用已通过隔离验收的b02ead56，补齐未足额开票订单和付款待核对发票的逐笔明细。分支`codex/srm-exit-exception-ledger`，仅更新5197/8095隔离预览，原5173/8080与原库不变。

采用服务端分页接口，复用现有风险判定SQL，避免在浏览器重算财务口径。按供应商关系确定租户和供应商；订单或发票模块权限及数据范围在查询和计数之前生效。汇总仍用于退出阻断，权限过滤后的明细数量可能少于汇总，不能以看不到明细为由放行。

页面新增两个页签，显示单据、状态、已知金额、具体异常原因及处理岗位。未知付款金额显示待核对。通过订单/发票详情入口进入原业务模块处理，不额外提供修改历史付款、手动消除风险或自动补造流水功能。

不建立重复财务账本，不增加数据库迁移，不把处理岗位标签表述为已分派责任人。

## 接口约定

GET `/api/v1/buyer/suppliers/{relationId}/exit-items`，kind为uninvoiced或payment-verification，page从1开始，pageSize为1至100。

返回items/total/page/pageSize。明细字段为id/orderId/invoiceId/label/status/amount/invoicedAmount/paidAmount/remainingAmount/reason/handlerLabel，未知金额允许空值。

## 实施顺序

1. 后端先补分页、隔离、权限、数据范围及判定一致性测试，再实现共享查询与API。
2. 前端补页签、服务端分页、状态切换清理、错误及权限反馈和原业务详情跳转。
3. 独立审查；运行针对性Java集成及前端回归、类型检查和构建。
4. 隔离真实HTTP、桌面与手机验收，更新实际交付边界并独立提交。

## 交付边界

原5173/8080与`procurement_saas_base`未切换、未写入；8095使用`srm_acceptance_20261023`。本轮无数据库迁移。测试只修改隔离环境专用fixture，保留异常样本供5197查看。

汇总风险不因当前账号看不到异常单据而解除；损坏的跨供应商发票关联不在本供应商明细中泄露，只保留汇总阻断与数量差异提示。处理岗位是职责提示，不代表已自动派单。财务历史数据修复、自动冲账及风险豁免不在本轮范围。
