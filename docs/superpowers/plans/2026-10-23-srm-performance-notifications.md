# SRM绩效任务站内通知

用户已授权按计划继续研发并减少常规确认。本批从bbb38150另建分支，不修改PR112待确认版本，不更新原5173或原数据。

## 设计与边界

- 复用现有站内通知和消息中心；不增加邮件短信、定时催办或新的审批引擎。
- 指派通知实际考核人；考核完成和供应商提交反馈通知本企业具备读取及维护权限的在职采购人员；整改、退回及关闭通知对应供应商具备资料读取及维护权限的在职人员。
- 按任务ID、事件、轮次版本、接收人生成去重键。通知与业务更新处于同一数据库事务，失败整体回滚；拒绝的业务请求不发通知。
- 消息只给出企业、周期、任务编号及办理位置，不复制内部评分、审批意见或整改材料。
- 不选用全企业广播，以免向无权限账号泄露业务；不新增队列，因为本批只有同库站内消息。

## 实施与验证

1. 先补数据库集成测试，覆盖指派、两轮整改、权限隔离、重复拒绝和通知回滚。
2. 增加绩效通知服务，挂接现有事件处理，复用notifyOnce。
3. Java回归、隔离8095真实HTTP及两端消息中心验证；原服务仅只读健康检查。
4. 记录结果并提交本批代码，与PR112独立交付。
