# 第二阶段：采购主流程整体闭环

**目标：** 一笔询比采购从需求、预算、采购计划到审批定标、订单合同、分批履约、结算及归档，金额、数量、状态和权限一致。

**基线：** main/4912535d（PR119），原系统5173—5176/API8080，原库procurement_saas_base。用户已授权本阶段开发、验收、PR合并及本机部署，无需中途确认；不得替换原数据。

**实现方式：** 保留React状态导航、Spring Boot模块化单体、Flowable唯一审批运行时、PostgreSQL/Flyway及MinIO。修复现有链路，不另造采购系统。新增受权限约束的项目执行/归档聚合，连接现有业务详情与真实档案。

## 冻结任务

- [x] 需求异常流：已驳回可编辑并重提，新实例保留旧历史；已有审批不可绕过。
- [x] 计划/询比：草稿可改期和取消并释放需求，保留审计；修正定标单与RFQ关联键及伪“免审”展示，处理相关写操作数据范围。
- [x] 预算：修正跨部门合并采购实付漏计；采用明确公开的分摊/待分摊口径，不伪造零金额或隐含预算硬拦截。
- [x] 分批履约：多批发货/收货、累计与逐行上限、头行一致、质量处置、并发锁；完整收齐才整单已收货。两端可继续办理剩余数量。
- [x] 合同与财务：普通编辑不能伪造审批状态/绕过受控变更；付款须通过真实数量质量与金额校验；归档按应付、开票、扣冲销实付和未决差异判断，未知历史数据阻断。
- [x] 项目执行与归档：展示真实需求/预算、定标、订单、合同、收货、发票付款和当前阻塞原因，可直达已有单据；不能以收货替代归档。形成受权限保护的归档快照及下载，附件缺失/权限不足不能静默漏项。
- [x] 本地统一验收：成功全链路、驳回重提、草稿取消重建、分批履约、数量及金额差异、跨租户/只读/部门范围；前端、Java全量回归、真实HTTP及桌面手机。完整CI另列最后交付门槛。
- [ ] 交付：原库/附件备份、副本迁移演练、PR/受保护合并、固定构建部署、四端真实登录、原数据与附件核验。

## 分工及边界

需求/预算/询比，订单履约，合同/财务为独立业务包；主任务负责执行归档、新文件、采购计划页面及集成交付。Maven统一运行，避免target并发污染。V218留项目归档，V219留多批履约，V220/V221仅确需时分别归财务/上游。

不扩商城、竞价、企业招标、AI、真实银行支付、税控、电子签章或外部接口。合同/付款是本地业务审批和登记，不把模拟或登记写成实际资金划转。退换货未处理须阻断付款，不擅自实现完整商城售后。既有无明确数量/付款基线的数据保留，必要时提示人工核对，不自动补造。
