# SRM评价任务与整改闭环

用户已授权依次推进阶段且不重复确认常规实现选择。本轮沿用Java模块化应用、React Query、现有私域合作关系及评价记录。

## 范围与设计

- 评价任务属于采购租户及具体供应商关系，每供应商每周期一条任务。指派本企业具备供应商维护权限的在职账号，记录截止日；只有实际指派人能完成评分。
- 评分调用现有考核服务，产生正式考核记录并绑定任务，不自动调级。
- 采购方可从已评价任务发起整改，填写要求与截止日期。供应商按企业身份看到属于自己的整改任务并提交文字反馈。采购方复核通过关闭，退回则再次反馈。
- 状态为assigned、evaluated、remediation_requested、remediation_submitted、closed；它是业务任务状态，不是新增通用审批运行时。通用审批继续以Flowable为唯一引擎。
- 每次变更保存真实操作人、时间、意见和审计，数据库事务及行锁防止并发重复推进。
- 采购方使用buyer:supplier:read/manage；供应商整改属于企业资料协同，暂复用supplier:profile:read/manage；后续独立权限拆分不在本轮。
- 不包括自动淘汰、真实账号分配修改、批量群发通知、配置化权重、周期内履约聚合、整改附件或客户生产部署。

## 实施分工

1. 后端：新增任务和历史表迁移、MyBatis映射、应用服务及控制器；测试状态、指派权限、租户和供应商隔离、重复推进。
2. 前端：采购方详情任务台账、任务新建与评分/整改/复核弹窗；供应商整改反馈模块。统一API客户端与实际接口契约一致；测试权限及状态操作。
3. 集成：原数据库保持不变；只在隔离8095数据库应用新迁移，5197/5198执行采购方至供应商往返闭环。同步OpenAPI。
4. 验收：全前端测试、两端构建、Java单测和定向集成、真实HTTP及桌面/移动浏览器验证；记录已完成与未发布边界。
