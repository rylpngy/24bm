# 统一项目库与需求、预算、采购执行

## 使用顺序

1. 采购方进入“项目库”，新建项目，填写部门、负责人、年度、资金来源、立项依据，选择物料并维护数量、预算单价、用途。立项金额按逐行金额四舍五入到分后累计，不再手工维护第二份总额。
2. 保存草稿后在独立详情页上传立项附件、核对明细并提交立项。流程配置器支持“项目立项”业务类型及其自定义表单、金额和部门条件。未发布自定义流程时采用受控的固定审批模板；必须有发起人以外的有效审批人。
3. 实际审批人在统一审批中心办理。通过、驳回、发起人撤回均记录真实 Flowable 历史；驳回或撤回可以编辑后重提，历史实例保留。审批中及已批准的项目不能直接改写立项资料或附件。
4. 立项通过后，可按立项明细生成采购需求草稿，或关联本部门、本年度、尚未转采购的已有需求。需求继续走原来的需求审批，不以立项批准替代采购需求批准。
5. 所有关联需求批准后，在项目详情创建询比或招标采购草稿，进入对应业务详情完善采购要求、邀请供应商、发布并执行。项目入口不会绕过采购方式原有权限、租户开通项、评审及定标要求。
6. 项目详情可追溯需求、采购执行、订单、合同、收货、发票及付款单据。汇总复用原业务数据和权限；缺少源模块权限或读取失败时明确提示，不将未知金额写成已完成或零余额。
7. 完成实际履约、发票付款及未决事项处理后，点击“核验并结项归档”。后台重新核验，生成原有采购执行归档 ZIP，再关闭项目。归档包含项目明细快照、立项及业务审批历史、业务台账和可核验的原附件。

## 预算口径

- 默认保留预警模式。部署不自动启用硬拦截或例外审批。
- 立项金额是规划金额，不额外扣减部门年度预算。
- 预算实际占用沿用需求审批、订单承诺和净付款口径。付款不是在承诺额上再次扣减。
- 招标转订单时，将项目需求关联到真实执行锚点，避免同一业务同时按需求和“无需求订单”占用预算。
- 结项复用原采购执行归档及预算结余释放机制。部门年度预算总览不是本项目专属资金余额；资金来源本轮是项目信息，不另建专项资金账。
- 原采购计划的多行需求没有保存逐行预算分摊时，显示“待核对”，不将需求总预算重复填入每一行。单位、规格和参考单价来自真实物料字段。

## 权限与数据

- 新增 `buyer:project:read`、`buyer:project:manage`。已有 `buyer:*` 角色自然覆盖；不会自动给原有细分角色扩权，管理员须按岗位配置。
- 项目与源单据同时受租户、数据范围和业务权限约束。项目负责人是业务字段，不意味着自动获得企业全部数据权限。
- 个人数据范围不开放部门年度资金汇总；跨部门、跨租户、外企业物料和无效负责人不允许绑定。
- 本轮数据库迁移仅新增三张空表，不回填或改写历史需求、订单及财务数据，不导入验收租户。

## 当前边界

- 一个项目本轮下发一条采购执行，可关联多条同部门、同年度需求；不支持跨年度混合、分包/多批多采购方式和立项批准后的变更审批。
- 已下发执行后不能修改需求集合；采购失败后的重启、分包和重新立项需后续受控变更能力，本轮不通过清空关联或删除历史绕过。
- 招标中标转订单保留现有汇总行模式，不用预算单价伪造中标逐项价格。
- 企业独立材料、共享服务及真实人员配置仍需管理员维护；不自动制造审核人、有效供应商资质或已批准预算。
- 正式统一认证、ERP/财务/支付、外部供应链及生产容量仍依赖客户环境，不属于本轮已完成的外部联调。
