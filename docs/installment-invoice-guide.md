# 分次开票与累计对账

## 业务入口

供应商端“销售订单”选择已足额收货的订单，点击“开具发票”。系统显示订单金额、累计已开金额、剩余可开金额以及各物料的已开/剩余数量。默认选择全部剩余数量，供应商可调整本次数量；填入发票号码、代码和税率后提交。未在本次开票的行可以填零或留空，金额由原订单单价和本次数量自动计算。零税率按零保存，不回退到默认税率。

保存后在订单开票区及“发票应收”查看每张发票。再次开票读取最新剩余数量，已开数量不重复复制。采购方在“发票付款”逐张核对、送审付款申请和付款批次、登记实际付款；两张分次发票不再因各自小于整单金额而产生虚假的金额差异。

## 校验与闭环

- 仅支持原订单单价，不提供直接改价入口；本次价税合计必须等于本次行金额合计，累计数量和金额不得超原订单。
- 同一提交编号、相同内容重试返回同一发票；相同编号改内容拒绝。同订单重复发票号码拒绝；并发请求先锁订单再核验余额。
- 历史发票无明细、来源行不明、原数量/金额不一致时暂停续开，不把历史缺失当成零。已清算订单不能新增开票，但原成功请求可用于重试核对。
- 分次发票的逐行对账展示“本票分次匹配”，未开本票的行仍显示“未开票”。付款检查仍要求足额验收、供应商一致、累计行数量/金额有效及差异已解决。
- 单张付款完成不代表合同已结清。合同归档和项目结项仍要求全部订单行累计开票足额、全部发票付款流水闭合及审批证据齐全。
- 分次发票可接入既有逐票清算，分别核验退款、补付款及最终发票/红冲凭证；不能用整体净额相同替代逐票核验。
- 不覆盖原始订单、验收、发票和付款历史；项目档案保留分次开票行、每张发票、审批、付款和附件原件。

## 精度及兼容边界

数量最多四位小数，价税合计按分核对。会造成剩余货款分币差异的拆分拒绝并提示调整数量，不自动改写原单价或已有发票。末次开票应覆盖全部剩余行，包含零单价物料；零金额发票不单独生成。

旧全额开票API保持兼容；请求未传行明细时仍按原规则校验全单金额及首张发票。新页面使用逐行开票与提交编号。增量迁移仅增加可空提交标识、指纹及相关校验，不回填或补造原有数据。

这是供应商发票登记和业务核验，不包含税控开具发票、自动红冲或真实银行划款。预算继续使用原预警模式。跨年冻结支出更正、专项资金分账仍待独立开发，不因本批交付而解除旧保护。

## 验收范围

按两次开票、分别审批付款、合同归档、采购执行与项目结项、ZIP下载验证正常路径；覆盖重试去重、并发、超量/超额、零税率、错误供应商、历史明细缺失及分次发票清算。验收在原库副本进行，原系统不导入测试项目或交易；发布前后核对原表原列和附件原件。
