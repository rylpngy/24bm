# 24Bid 按规范重写落地方案

> 生成时间：2026-06-24
> 依据：`SaaS 管理系统研发标准 v1.1`、`docs/产品需求理解.md`、`docs/供应商SRM需求设计.md`、`docs/标准对标差距分析.md`、`docs/后续研发路线.md`
> 前端样式：完全复刻现有实现（换底层用料，不换观感）。

## 0. 核心判断：后端演进，前端重建

| 层 | 处境 | 策略 |
|---|---|---|
| 后端 | 已是模块化单体 + MyBatis + PostgreSQL，**大体合规** | **原地演进**：加装 Keycloak/Flowable/MinIO/Redis/ArchUnit/领域事件/springdoc，业务逻辑保留并补强 |
| 前端 | 单 App.tsx 21k 行、三端同 bundle、自研栈 | **重建**：拆 monorepo、运营后台独立、shadcn + TanStack 重写组件，逐切片替换 |

整体采用**绞杀者模式**：在现仓内建新结构，按垂直切片把旧实现逐条替换，旧代码作为业务/样式的对照参照，直到切完退役。**不另起空仓**——保留 git 历史、可持续对照校验、样式直接搬。

## 1. 目标工程结构（monorepo，现仓内演进）

```
24Bid/                          # 现仓，原地演进
├── apps/
│   ├── platform-admin/         # 🆕 运营后台独立 app（安全隔离，私有化常不交付）
│   └── tenant-portal/          # 🆕 采购方 + 供应商合并，角色路由区分
├── packages/
│   ├── ui/                     # 🆕 shadcn/ui + Radix 复刻的组件库（StatusPill/Panel/...）
│   ├── api-client/             # 🆕 orval 从 OpenAPI 生成的 client + TanStack Query hooks
│   └── shared/                 # 🆕 共享类型、Zod schema、工具、设计 token
├── backend-java/               # 原地演进的 Spring Boot 模块化单体
├── infra/
│   └── docker-compose.yml      # 🆕 postgres + redis + minio + keycloak（+ 后续 flowable 同库）
├── App.tsx / data / services   # 旧前端，切片替换中保留为参照，切完退役
└── docs/
```

工具：**pnpm workspaces + Turborepo**。

## 2. 后端模块分层（标准三层 + 横切）

沿用现有 16 上下文，按标准归位，并补强：

- **基础平台层**：`tenant`、`identity`(→ Keycloak)、`organization`、`dictionary`、`platform`
- **主数据层**：`catalog`、`supplier`(→ **强化为 SRM 限界上下文**：档案/准入/分级/资质/绩效/风险)
- **核心业务链路层**：`demand`、`sourcing`、`order`、`finance`、`contract`
- **横切**：`approval`(→ Flowable 规则配置式)、`notification`、`attachment`(→ MinIO)、`audit`

规范护栏：
- **ArchUnit** 守层间依赖方向（上层依赖下层、横切不反向依赖业务）。
- **领域事件**（Spring ApplicationEvent）解耦跨模块/横切：上游发事件，下游订阅（如"定标通过"→生成订单、"发货"→通知+审计+合同履约事件）。
- **每模块独占表，跨模块只调 Service**（现状基本满足，补 ArchUnit 兜底）。

## 3. 契约工具链（正向契约，消除前端手写）

```
后端 controller 注解 ──springdoc──▶ /v3/api-docs (OpenAPI)
                                        │
                          orval / openapi-typescript
                                        ▼
              packages/api-client：类型 + TanStack Query hooks
              packages/shared：Zod schema（表单校验 / 响应解析同源）
                                        │
                         orval mock / Prism ──▶ Mock Server（前后端并行）
```

替代现有 `data/apiContract.ts` 前端手写契约。`openapi:check` 改为对标后端生成物。

## 4. 重器引入时机（不一次全上，按切片驱动）

| 重器 | 引入切片 | 触发理由 |
|---|---|---|
| Keycloak | S0 地基 | 认证是所有切片前置 |
| springdoc + orval + shadcn 组件库 | S0 地基 | 决定所有后续代码形状 |
| ArchUnit + 领域事件 | S0 地基起，持续 | 护栏越早越省 |
| MinIO | 首个带附件的切片（需求/资质） | 真实文件存储 |
| Flowable（规则配置式一期） | 审批切片（S1） | 审批从固定模板升级 |
| Redis | 出现缓存/会话/锁真实需求时 | 不提前做 |

## 5. 垂直切片序列（每片端到端，复刻样式）

依赖顺序推进，每片 = DB → service(+领域事件) → controller(+springdoc) → orval hooks → shadcn UI(复刻旧样式) → Playwright e2e → 验收文档。

| 切片 | 范围 | 关键标准项 / 产出 |
|---|---|---|
| **S0 地基** | monorepo 骨架 + 工具链 + shadcn 组件库复刻 + Keycloak 认证 + 三端 workspace 壳 + docker-compose | 打通 springdoc→orval、ArchUnit、运营后台独立、组件库逐像素对齐旧样式。**跑通即里程碑。** |
| **S1 需求 + 审批** | 采购需求 CRUD/提交，审批中心（Flowable 规则配置式一期） | 主流程起点 + Flowable 落地 + MinIO（需求附件） |
| **S2 供应商 SRM** | 准入(含自助注册入驻) + 等级/生命周期标记 + 资质(到期预警) + 多维周期绩效考核驱动调级 | 按 `docs/供应商SRM需求设计.md` 的 MVP 闭环 |
| **S3 物料目录** | 物料主数据 CRUD/启停/编码唯一（轻） | RFQ 前置主数据 |
| **S4 RFQ→报价→比价定标** | 询价创建/邀请 → 供应商报价 → 比价矩阵 → 定标审批 | **标准对标核心**：TanStack Table 比价矩阵 + 跨端协同 + 契约全链路 |
| **S5 订单履约** | 生成订单 → 供应商确认 → 发货 → 收货 | 一单一节点唯一约束 + 领域事件链 |
| **S6 财务结算** | 发票 → 三单匹配 → 付款状态 | 金额一致性、黑名单拦截 |
| **S7 合同** | 台账 → 审批 → 履约事件 → 归档 | 订单后置闭环 |
| 平台运营 | 租户/企业审核/公告 | 穿插或最后，轻量 |

> SRM(S2) 排在 RFQ(S4) 之前：RFQ 邀请资格依赖"已准入 + 有效资质 + 非淘汰/黑名单"。

## 6. 前端样式复刻策略

- 把现有约 30 个组件（`StatusPill`/`Panel`/`ListToolbar`/`ResponsiveTableFrame`/各模块色卡片/反馈面板…）用 **shadcn/ui + Radix 重建到 `packages/ui`**，但 className 语义、配色（blue-600 主色、emerald/amber/slate 语义色、模块色）、间距、字重、状态色**逐像素对齐**现状。
- `StatusPill` 的中文状态→配色映射、布局壳（深色侧栏 + 顶栏 + max-w-7xl）原样搬。
- 验收每片时用截图/视觉对照旧实现，确保"换用料不换观感"。

## 7. 里程碑与节奏

```
S0 地基(1-1.5w·里程碑) → S1 需求+审批 → S2 SRM → S3 物料 → S4 RFQ链路(对标核心)
   → S5 订单 → S6 财务 → S7 合同 ；平台运营穿插
```

- 每片独立可验收、可演示；旧代码同步退役。
- 后端 mvn test + 前端 vitest/Playwright + ArchUnit + openapi:check 组成 CI 门禁（标准要求补 CI）。
