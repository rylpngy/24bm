# 统一身份接入与账号映射操作说明

## 使用入口

采购方“团队与权限→统一身份”。仅有`buyer:role:manage`的企业管理员可查看和修改。页面包括当前配置状态、待接入事项、账号映射、搜索和服务端分页。不提供明文密钥、令牌或任意URL探测。

“已配置”只说明当前服务器参数存在，不说明已通过客户网络、证书、登录或业务联调。原系统默认继续兼容现有登录，不自动切生产配置。

## 建立及维护映射

1. 先在团队成员中维护在职成员、工号、部门和本地角色。成员资料可继续用既有导入功能维护。
2. 运维核对可信身份源`keycloak.issuer-uri`和公钥服务`keycloak.jwk-set-uri`，正式环境还须受众`keycloak.audience`。页面未配置issuer时不可新建，不能凭用户自行输入的URL信任新身份源。
3. 由客户身份管理员提供实际令牌的稳定`sub`标识。sub不一定等于工号、邮箱或姓名，不能猜测或将密码填入。选择本地成员、填写外部标识和绑定依据，保存映射。
4. 取得新令牌登录验证。系统先验证签名、有效期、issuer和已配置的audience，再按issuer+sub关联本地采购方成员。外部令牌中的角色、租户和系统用户ID不覆盖已建立的映射；权限及数据范围仍由本系统实时读取。
5. 停用映射后，后续请求立即拒绝；已进入处理中的请求不能追溯撤销。停用本地成员或移除本地角色同样阻止外部访问。启用映射不会启用已停用的成员。
6. 恢复或“重新绑定”之后，旧令牌不能继续使用，需要重新登录。请等待至少1秒再获取新令牌，以避开签发时间的秒级精度。重新绑定只可选本企业在职且已授权成员，原映射ID及审计保留，身份源和sub不直接改写。
7. 版本校验阻止旧页面覆盖新结果；操作须填写原因。不能停用或重新绑定自己的映射，需另一管理员处理。不删除原账号、历史单据及审批签署。

同一issuer+sub不能同时绑定到不同企业。当前交付支持一个外部身份映射到一个采购方成员；跨企业身份选择、多身份源、自助绑定、SCIM/HR增量事件同步及第三方账号创建协议不在本轮，不冒称已自动同步。错误绑定可以通过受控重新绑定纠正，不能通过删除记录规避审计。

## 严格模式及上线顺序

`keycloak.buyer-identity-mapping-required`默认false：未登记采购方外部身份保留既有受信令牌字段映射；一旦登记，停用/过期签发时间的记录不能回落绕过。true时未登记的采购方身份一律拒绝，并在启动时要求开启外部身份及配置issuer、audience、公钥服务。该开关只控制采购方；平台及供应商沿用既有签名scope和本地在职账号/角色核验，并不因此被标为已完成显式映射。将采购方账号伪装成其他scope也无法通过本地账号归属检查。

正式切换前先备份、核对全部成员和至少两个管理员映射，在测试环境验证登录、退出、停用、角色调整、数据范围及应急恢复，再由运维显式切严格模式及prod配置。严格模式只约束外部令牌，不替代现有prod关闭本地自签令牌的安全配置；本地验收允许的自签管理员入口不是生产应急方案。不要直接在现用原系统启用严格模式造成已有账号无法登录。

## 尚需客户条件

客户登录协议/issuer/受众/证书、公钥访问、真实sub字段及人员生命周期事件、SSO客户端和重定向地址、登录退出机制和应急管理员安排。当前登录页沿用既有Keycloak流程，不声称已实现客户CAS、SAML、扫码或授权码单点登录适配。

供应链、财务、支付及正式模型仍需真实接口和授权；生产容量、RTO/RPO、安全测评须按客户规模验收。现有恢复和只读容量工具可复用，本批不新增虚假回执或模拟成功状态。

## 本地开发验收

`ExternalIdentityIT`使用独立PostgreSQL、真实RSA/JWKS和随机HTTP端口验证严格映射、篡改角色/租户不越权、停用/恢复/重新绑定、成员停用及本地角色移除。

`scripts/identity-readiness-acceptance.mjs`仅允许8095且进程DSN匹配25432的`identity_readiness_*`，显式授权后在副本创建隔离业务样本，使用本机Keycloak真实签发令牌核验兼容模式下的映射权限、启停、重绑及审计。不要在原8080运行写验收，不将其报告视为客户身份环境验收。
