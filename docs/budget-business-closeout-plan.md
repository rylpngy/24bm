# 预算业务闭环执行范围

基线：PR126/main `503dffd45ee6532caec36e1a1ca7031b38568282`。默认预警，不改变历史预算，不替换原数据。

## 本批交付

1. 部门年度预算编制、草稿编辑、提交Flowable、驳回重提、发起人撤回、审批后生效。调整使用独立申请，保留原额度和版本，过时申请不得覆盖新额度。
2. 预警、超额例外审批、硬拦截三种企业策略。未配置继续预警；非预警策略由有权限人员明确启用。例外按部门/年度和具体需求或项目授权，只用一次，限额、有效期和预算版本均校验。
3. 统一占用明细：在审需求预占，已通过需求正式占用；驳回/撤回释放。需求关联订单不重复相加；订单或实付超过需求基线时取较大暴露额。项目有效归档结算后释放未使用额度，实际支出仍计入年度使用额，付款不二次扣预算。
4. 商城及招标等无需求来源的新订单按经办人有效部门和上海自然年度归属；历史无归属订单不猜测、不回填原单据，提供受控预算归属维护。信息未核对时不允许启用强控制。
5. 额度、占用、余额、预警、明细与导出使用同一计算服务。并发提交及下单在服务端串行核验，失败回滚，不只限制按钮。
6. 预算工作区提供总览、编制/调整、例外申请、占用台账及策略配置；流程配置器和全局审批中心识别预算业务。

## 保持边界

- 取消项目不等于采购需求消失：未执行需求仍保留其需求占用，避免释放后继续重复采购。撤回/驳回需求才释放预占；采购结算需真实归档证据。
- 预算以部门年度为粒度，不扩展专项资金、多币种、税控或资金划拨；实付仅来自已有正负付款流水。
- 历史不完整数据明确列为待核对，不能当作已支付零元。默认预警允许既有业务继续；强控制不能隐瞒未归属责任。
- 所有业务写入验收使用隔离库。新增表迁移先在原库备份副本验证，旧表原字段及原附件摘要必须保持一致后再发布。
- 定向测试跟随开发，完成业务后统一全量回归、真实HTTP/浏览器、PR CI、合并、固定构建和保留原数据部署。
