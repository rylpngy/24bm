## 开场口径

这一段演示的是阶段十合同管理承接订单，不是完整法务合同系统。合同管理在当前产品里的定位是：采购订单生成后，采购方可以把订单沉淀为合同台账，再围绕合同审批、履约事件、收货验收、发票付款和归档边界做演示级闭环。

讲解时先强调三件事：

- 阶段十合同演示总线：把订单、合同、审批、收货、发票付款串成一条讲解线。
- 推荐合同样本：现场优先围绕一条稳定样本讲，不临时找数据。
- 合同演示动作闭环：把提交合同审批、推进履约、处理收货验收、处理发票付款和归档合同集中到合同详情第一屏。

## 演示顺序

### 1. 采购订单

讲解重点：订单生成合同。

先从采购订单页说明合同不是凭空创建，而是承接已生成的采购订单。订单里有供应商、金额、履约状态和预计到货，这些信息会成为合同台账的来源。

现场话术：采购订单是合同的业务来源，合同管理不是独立孤岛，而是订单履约继续向审批、履约和归档延伸的承接层。

### 2. 合同管理

讲解重点：阶段十合同演示总线、推荐合同样本、合同演示动作闭环。

进入合同管理页后，先看页面顶部的阶段十合同演示总线，按四条主线讲：

- 订单生成合同。
- 合同审批。
- 合同履约事件。
- 合同与订单/发票/付款关系。

然后定位推荐合同样本，打开合同详情。合同详情第一屏先讲合同演示动作闭环：

- 提交合同审批：把合同送入审批中心。
- 推进履约：演示合同状态推进和履约进度反馈。
- 处理收货验收：跳转到收货验收页，保留合同上下文。
- 处理发票付款：跳转到发票付款页，保留合同上下文。
- 归档合同：只有归档条件满足时才允许提交 Java 服务端门禁。

现场话术：这不是新增一套合同工作流引擎，而是把当前已有的真实按钮和页面跳转整理成演示闭环，方便业务人员一眼理解下一步该做什么。

### 3. 审批中心

讲解重点：合同审批。

从合同详情提交审批后，切到审批中心讲合同审批任务。这里重点说明审批中心统一承接采购需求、供应商准入、定标审批和合同审批，合同审批通过后回写合同状态。

现场话术：当前是单级审批演示能力，重点证明合同审批任务可以进入采购方内控队列；多级会签、审批意见持久化和流程可视化配置不在本轮声明范围。

### 4. 收货验收

讲解重点：合同履约事件。

从合同详情点击处理收货验收，页面会聚焦合同关联订单。完成收货后，合同详情可以回看履约事件，用于解释合同履约节点如何沉淀证据。

现场话术：收货验收是合同履约证据之一，合同页不会替代收货模块，而是通过上下文联动把收货结果纳入合同复核。

### 5. 发票付款

讲解重点：合同与订单/发票/付款关系。

从合同详情点击处理发票付款，页面会聚焦合同相关发票。付款登记仍在发票付款模块完成，合同页只做关系聚合、付款计划只读展示和归档复核提示。

现场话术：当前只登记付款状态和审计留痕，不触发真实支付；合同与发票付款的关系用于演示业务闭环，不声明已完成税控、支付或完整财务集成。

## 收口口径

合同阶段十现在可以演示一条完整讲解线：

采购订单生成后形成合同台账，合同进入审批中心，合同详情通过动作闭环跳转到收货验收和发票付款，最后用归档门禁解释为什么合同不能随意归档。

对业务方可以说：阶段十让合同管理从“合同列表”变成了“承接订单的演示闭环”。对技术方可以说：本轮没有扩张后端接口，仍复用已有 Java API、页面状态切换和视觉验收脚本。

## 现场异常兜底

- 如果页面出现加载失败，先检查 Java 健康接口和 `http://localhost:3000/` 是否可访问。
- 如果看不到推荐合同样本，先运行 `node scripts/stage-ten-contract-demo-path-check.mjs` 复跑视觉证据，再刷新合同页。
- 如果动作按钮不可点击，优先讲按钮下方的动作反馈和下一步承接，说明当前样本状态已经进入只读或门禁未满足。
- 如果需要证明主流程仍稳定，运行 `node scripts/stage-seven-onsite-demo-acceptance-check.mjs`，确认 17 个真实动作失败数为 0。
