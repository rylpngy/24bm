# 24Bid 产品业务框架说明

> Updated: 2026-07-09
> Purpose: 统一记录 24Bid 的产品业务边界、版本范围和核心业务模块口径，作为研发、设计和验收的业务事实源。

## 1. 产品定位

24Bid 是面向企业采购场景的轻量化数字采购协同平台，1.0 版本优先覆盖采购方内部采购管理、供应商私域协同、采购执行、订单合同、收货发票付款等主链路。

1.0 的核心目标不是一次性覆盖完整招投标法规场景，而是先形成可演示、可试点、可逐步加厚的企业采购闭环。

## 2. 版本边界

### 2.1 1.0 版本支持范围

1.0 版本先明确两个独立业务维度：

- 采购方式：决定采购执行路径，即“怎么采购”。
- 供应商征集方式：决定是否限定具体供应商，即“向谁征集”。

1.0 版本采购方式只支持四类：

| 采购方式 | 业务含义 | 1.0 目标 |
|---|---|---|
| 询比 | 面向多个供应商发起询价/报价，对报价进行比较并定标 | 企业日常采购主路径 |
| 竞价 | 供应商围绕采购需求进行价格竞争，形成竞价结果 | 价格敏感类采购路径 |
| 商城 | 从标准化商品/物料目录发起商城化采购 | 高频低值、标准品采购路径 |
| 单一来源 | 面向确定供应商的定向采购，需要明确来源依据与审批留痕 | 定向采购路径 |

1.0 版本供应商征集方式支持两类：

| 供应商征集方式 | 业务含义 | 适用说明 |
|---|---|---|
| 公开 | 不预先限定具体供应商，符合条件的供应商可参与响应 | 可用于询比、竞价 |
| 邀请 | 预先限定具体供应商范围，从供应商库选择候选供应商 | 可用于询比、竞价 |

1.0 版本围绕上述采购方式和供应商征集方式设计页面、菜单、数据模型、演示数据和验收用例。采购需求合并生成采购计划后，应先确定采购方式，再确定是否限定供应商范围。

### 2.2 2.0 版本保留扩展范围

以下方式作为 2.0 版本扩展，不作为 1.0 功能验收范围：

| 保留方式 | 延后原因 |
|---|---|
| 公开招标 | 涉及更完整的公告、公示、投标、开标、评标、专家、保证金、法规合规流程 |
| 邀请招标 | 与正式招标流程强相关，需要补齐招标文件、投标文件、评审及合规留痕 |
| 竞争性谈判 | 需要多轮谈判、谈判纪要、谈判小组和轮次合规规则 |

这些能力可以在代码和数据模型中保留扩展空间，但 1.0 页面上不应作为主操作路径暴露给普通用户。

## 3. 核心业务模块地图

### 3.1 PM 采购管理

- 预算管理：预算池、预算占用、释放、执行率和预警。
- 采购需求：需求创建、物料明细、提交审批、审批流转、需求合并。
- 采购计划：由一个或多个已审批需求形成采购方案，确定预算、时间、地点、执行方式和后续采购路径。

### 3.2 采购执行

- 询比项目：供应商邀请、报价收集、报价对比、定标。
- 竞价项目：竞价规则、竞价过程、竞价结果。
- 商城采购：标准物料/商品检索、选品、下单。

### 3.3 SRM 供应商管理

- 供应商列表：私域供应商池、状态、等级、授权品类、绩效概览。
- 智能寻源：供应商发现、候选推荐、品类匹配。
- 邀请管理：供应商邀请、注册/入驻进度。
- 准入管理：准入资料、准入审批、准入状态流转。
- 绩效管理：周期考核、评分、调级建议。
- 资质管理：资质证照、有效期、到期预警。

### 3.4 采购协同

- 采购订单：定标或商城采购后的订单生成与状态跟踪。
- 合同管理：合同台账、审批、履约、里程碑、付款关联。
- 收货验收：到货、验收、质检、合格率。
- 发票付款：发票登记、三单匹配、付款登记。
- 付款批次：批量付款申请、审批、执行和异常处理。

### 3.5 BI 采购分析

- 采购业务概览：采购金额、订单、供应商、成本节约等核心 KPI。
- 关键价格指标：关键物料价格趋势、市场对标、价格异常。
- 采购支出分析：品类、部门、供应商维度的支出结构和降本洞察。

### 3.6 系统配置

- 物料库：物料分类、物料主数据、导入、检索、详情。
- 流程引擎：审批流程模板与节点规则。
- 组织架构：部门、人员、岗位。
- 团队与权限：角色、权限、数据范围。
- 审计日志：业务操作、审批、数据变更留痕。

## 4. 1.0 采购计划到执行规则

采购需求合并生成采购计划时，1.0 的采购方式字段应收敛到：

- 询比
- 竞价
- 商城
- 单一来源

供应商征集方式与供应商选择规则应按采购方式分别设计：

| 采购方式 | 供应商征集方式 | 供应商选择 |
|---|---|---|
| 询比 | 公开 / 邀请 | 公开时不限定供应商；邀请时从供应商库选择多个供应商，后续支持 AI 推荐候选 |
| 竞价 | 公开 / 邀请 | 公开时不限定供应商；邀请时从合格供应商中选择多个候选 |
| 商城 | 不适用 / 目录采购 | 不以邀请供应商为主，而是以物料/商品目录和供应商货架为主 |
| 单一来源 | 定向 | 定向选择 1 家供应商，需保留来源说明和审批依据 |

“公开/邀请”在 1.0 中是供应商征集方式，不等同于“公开招标/邀请招标”。正式招标类采购方式若仍存在于历史代码或数据中，应视为 2.0 预留能力，不应影响 1.0 主流程页面设计与验收。
