# 阶段五合同管理 MVP 信息架构

## 目标

合同管理 MVP 的第一轮目标是补齐采购方后台里的合同业务入口，让合同成为订单、供应商、履约和财务之间的承接层。

本轮只做信息架构和验收边界，不新增 Java API，不新增数据库表，不接电子签章或外部合同系统。第一轮不新增 Java API，后续等页面结构和字段稳定后，再进入 Java 合同台账设计。

## 采购方菜单入口

采购方企业端建议新增一级菜单：合同管理。

菜单位置建议放在采购订单之后、收货验收之前。原因是合同通常从定标和采购订单生成后进入草案阶段，并在收货、发票付款前持续约束履约。

建议采购方菜单顺序调整为：

1. 首页看板
2. 采购需求
3. 审批中心
4. 供应商库
5. 物料目录
6. 询价项目
7. 报价对比
8. 采购订单
9. 合同管理
10. 收货验收
11. 发票付款
12. 审计日志

## 主流程

阶段五合同管理 MVP 的主链路为：

采购订单 → 合同草案 → 合同审批 → 合同生效 → 履约跟踪 → 合同归档。

这条链路只表达平台内合同协同状态，不代表电子签章完成、法务审查完成或外部合同系统已同步。

## 页面结构

### 合同台账

合同台账用于采购方快速查看合同总量、审批状态、履约风险和即将到期合同。

核心列表字段：

- 合同编号
- 合同名称
- 供应商
- 关联采购订单
- 合同金额
- 合同状态
- 签订日期
- 生效日期
- 到期日期
- 履约进度
- 归档状态

首轮筛选建议：

- 全部合同
- 草案
- 审批中
- 已生效
- 履约中
- 即将到期
- 已归档

首轮操作建议：

- 从采购订单生成合同草案
- 提交合同审批
- 查看合同详情
- 查看履约摘要
- 查看合同附件

### 合同详情

合同详情用于承接合同基础信息、关联业务对象、履约进度和审计事实。

详情分区建议：

- 基础信息：合同编号、合同名称、合同类型、采购方、供应商、合同金额、币种、经办人。
- 关联对象：关联采购订单、关联供应商、关联采购需求、关联询价项目。
- 日期信息：签订日期、生效日期、到期日期、归档日期。
- 合同状态：草案、审批中、已生效、履约中、已完成、已归档、已终止。
- 履约摘要：订单状态、收货验收状态、发票付款状态、履约进度。
- 合同附件：合同正文、补充协议、验收证明、履约附件。
- 审计记录：创建、提交审批、审批通过、审批驳回、生效、归档。

### 合同审批

合同审批第一轮复用现有单级审批模型。

关键动作：

- 提交合同审批
- 审批通过
- 审批驳回
- 查看审批摘要

审批摘要建议包含：

- 合同编号
- 合同名称
- 供应商
- 合同金额
- 关联采购订单
- 申请人
- 当前状态

### 履约跟踪

履约跟踪第一轮从已有业务对象派生，不自动改写订单、收货或财务状态。

关联采购订单：展示订单状态、订单金额、供应商确认状态。

关联收货验收：展示收货进度、验收状态、异常验收提示。

关联发票付款：展示发票金额、付款申请状态、付款批次、付款归档状态。

首轮履约指标建议：

- 订单履约进度
- 收货完成度
- 发票开具进度
- 付款登记进度
- 即将到期提醒

### 合同归档

合同归档表示合同在平台内进入只读审计状态。

归档后只读边界：

- 归档后不允许继续编辑合同基础信息。
- 归档后不允许重新提交合同审批。
- 归档后只允许查看合同详情、履约摘要、附件和审计记录。
- 后续如需变更，单独设计合同变更申请，不在第一轮实现。

## 数据字段草案

合同对象首轮字段建议：

- `contractNo`：合同编号
- `contractName`：合同名称
- `supplierId`：供应商 ID
- `supplierName`：供应商名称
- `buyerTenantId`：采购方租户 ID
- `relatedOrderId`：关联采购订单 ID
- `contractAmount`：合同金额
- `currency`：币种
- `contractStatus`：合同状态
- `approvalStatus`：审批状态
- `fulfillmentStatus`：履约状态
- `archiveStatus`：归档状态
- `signedAt`：签订日期
- `effectiveAt`：生效日期
- `expiresAt`：到期日期
- `ownerId`：经办人
- `createdAt`：创建时间
- `updatedAt`：更新时间

合同附件首轮字段建议：

- 附件 ID
- 合同编号
- 附件类型
- 文件名
- 上传人
- 上传时间

## 边界

- 第一轮不新增 Java API。
- 第一轮不新增数据库表。
- 第一轮不做电子签章、法务红线批注、真实付款或外部合同系统集成。
- 第一轮不自动改变采购订单、收货验收、发票付款或付款批次状态。
- 合同审批先复用单级审批模型，不做多级审批、会签和审批流可视化。
- 合同归档先做只读审计边界，不做合同撤销、变更申请或归档解冻。
- 供应商绩效基础评分仍作为后续方向，不在本轮并行启动。
