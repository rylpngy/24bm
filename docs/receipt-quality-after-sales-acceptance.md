# 不合格验收与退换货清算联动

## 使用入口

收货验收 → 不合格验收记录 → 处置复核 → 退换货质量核销。

1. 保留原收货量、合格量、质检结论和处置意见，不把原不合格验收改成合格。
2. 从关联订单申请退货或换货，完成寄回、供应商签收；换货还要补发及买方合格复验，最后双方确认处理结果。
3. 复核人选择具体验收明细和同订单行已核验的售后单，填写依据，确认质量核销。
4. 核销量由售后单带入，不允许超过本验收批次剩余不合格数量。一张售后单只可使用一次，分批责任须分单办理。
5. 换货核销后恢复正常三单匹配、付款及归档判断；退货核销后仍须进入合同/订单清算，核对保留货物金额、到账退款或补付款及发票/红冲原件。
6. 采购执行和项目 ZIP 保存原质检、售后历史、实物原件、质量核销人/时间/依据及清算审批与资金证据。

## 边界与控制

- 需有验收管理及审批复核权限；订单、验收批次和售后须属于当前租户及数据范围，不接受跨订单行关联。
- 仅完成实物核验且由买方确认的退货/换货可核销；维修、仅文字回复、未复验、已拒绝或已撤回记录不能替代质量证据。
- 未核销、部分核销、数量异常及头行质检不一致继续拦截，不因状态标签或 AI 意见自动放行。
- 让步接收与退换货核销互斥，防止对同一不合格量重复接受；已有部分核销时剩余责任继续按退换货处理。
- 已归档、进入合同清算或已清算的记录不可补写质量核销；历史完成单也须先核验实物证据。
- 凭证和核销记录不可覆盖或删除，重复同内容提交不重复记账；不同内容不得覆盖原记录。
- 预算仍为预警模式，退款仍为到账凭证登记/核验，不包含银行自动划款、税控或客户环境集成。
- 多合同、多发票分摊及历史付款不明继续沿用既有清算拦截，不通过猜测金额降低责任。

## 验收

- 数据库回归覆盖不合格换货核销、保留原始质检、退货后已知预付款退款、预算净额、重复/越界/超量核销及不可变记录。
- 隔离数据库 HTTP 验收启用 `PROJECT_RECEIPT_QUALITY_ACCEPTANCE=1`，覆盖原始部分不合格 → 实物交接 → 质量核销 → 付款或清算 → 项目归档。
- 所有测试写入隔离库；原系统备份后先在副本迁移，原数据及附件不替换、不清理，预算策略不变。
