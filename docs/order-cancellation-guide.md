# 未履行订单协商取消

## 办理

1. 采购方进入采购订单详情，在“订单取消协商”中填写原因并申请。仅支持未发货、无合同、无发票、无收货和售后记录的订单。
2. 申请期间状态为“取消协商中”，暂停供应商确认、发货、采购方维护和新建合同。供应商在销售订单明细中查看原因，填写意见后选择同意或拒绝。
3. 供应商同意后订单成为“已取消”，原金额、明细、来源及时间保留；按原始SKU和数量恢复可核验库存。同一确认重复提交不会重复回库。
4. 拒绝或原申请人撤回后恢复申请前的订单状态，不改变库存。页面只向相应角色展示办理按钮，服务端再次校验角色、企业、数据范围和发起人。
5. 取消记录按页展示双方账号、原因、意见和时间。取消不是付款审批，也不会生成虚假收货、发票或付款记录。
6. 项目包及采购执行结清时仍核验完整证据；核验通过后订单实际责任为零、释放结余。未结清前需求预算仍保留，避免取消订单即绕过项目审批挪用额度。归档保留原始订单及完整取消台账。

## 边界

- 本批是无合同、无发货及财务责任订单的双方协商取消，不是已签合同解除或独立的内部取消审批流程。
- 已有合同（包括草案）、任何发货/收货/发票或售后记录、已归档项目及在审项目变更/承接清算均阻断。库存历史无法核验则整体回滚，不推算回库。
- 已签合同解约、补偿、部分履约减量、退货退款、红字发票、外部供应链订单撤销和专项资金分账仍待后续独立实现。
- 不删除原单据、不改写旧迁移，保留原系统数据及预算warning模式；验收数据仅在隔离库生成。
