# 跨年度冻结付款的部分金额更正

## 本批范围

原付款已随项目跨年度承接、资金归属可核验，且项目仍批准有效、合同未归档、订单未进入清算时，可按实际更正依据对原付款的部分金额申请独立审批。一笔原付款允许先后办理多次更正，每次单独申请、确认金额并审批；同一原付款只能有一个在审申请。

该功能是付款登记与年度责任的受控更正，不自动退款、不代替财务总账调整，不允许借更正改写已付来源或恢复已结束履约。

## 办理步骤

1. 发票详情打开“跨年冻结付款更正”，查看原付款金额、剩余可更正金额、原责任年度及当前承接年度。
2. 选择原付款，填写本次更正金额、更正凭据号和原因。金额须大于零、最多两位小数且不超过剩余可更正金额。
3. 对专项资金，逐个填写涉及原来源的本次金额，明确选择当前年度回补来源。不涉及的来源可留空；合计必须等于本次金额，每个来源不得超出其剩余可更正金额，合并回补不得超出当前来源可用额度。
4. 提交当前已发布的审批流程，由独立办理人核对。提交、撤回、驳回均不改变付款净额或资金责任；批准时重新核对原付款、历次冲销、项目版本、资金来源与可用额度及合同里程碑。
5. 批准后追加本次负数流水。专项资金沿原版本、原来源冲回本次金额，并等额恢复当前年度未付责任。合同里程碑仅扣减本次金额，不整笔清空。
6. 余额仍在原责任年度冻结，后续可再申请。旧正向流水、历次审批、更正凭据、原承接快照均保留；台账分页展示。
7. 业务详情与统一审批详情显示送审时金额依据、批准后预计原流水剩余及来源明细。这是该次送审依据，不冒充后续实时余额。
8. 后续重新登记付款、完成正常履约后，合同归档、分包/项目结项及执行ZIP纳入每次更正审批、反向流水、来源回补和原承接证据。

## 示例

原年度付款200元，A来源150元、B来源50元，跨年后未付责任1000元：

- 首次更正60元，明确A冲回40元、B冲回20元。原年实付剩余140元，当前未付责任1060元。
- 再次更正40元，只冲回A来源40元。原年实付剩余100元，当前未付责任1100元。
- 原正向200元及两次负向60/40元均保留，原承接快照不改写。后续当前年度登记付款800元，累计净付款900元；结项释放未用责任300元。

## 兼容与边界

- 旧客户端未传本次金额时，按提交当时全部剩余金额办理；原来尚在审批中的整笔申请仍按其原冻结依据验证。
- 普通“直接冲销”仍不支持部分或多次冲销，也不能绕过跨年冻结保护。数据库仅允许真实已批准的冻结更正关联多次部分负向流水。
- 数据库保留原付款、原来源版本、累计金额上限、当前容量、审批人与资金回补一致性保护；不修改历史迁移文件，不推算缺失的历史来源。
- 已清算订单、已归档合同及关闭项目的复杂冻结更正仍拦截；现有受控项目重开不自动解除合同/清算保护。
- 原付款同时分摊多个仍有余额的合同里程碑时，部分更正须先明确分项。本批不猜测扣减哪个节点，提交前即拦截；整笔冲回仍按原分配办理。无里程碑或单一有效里程碑的部分更正正常支持。
- 新资金来源引入、历史已付来源改归属、混合补偿历史分账及外部银行/财务接口不属于本批。
- 保持预算默认`warning`。专项资金来源额度独立校验，不受预警模式豁免；原系统及原有数据不以验收库替代。

## 本地验收入口

`scripts/partial-frozen-correction-acceptance.mjs`仅允许8097/5201隔离服务，必须显式设置`ACCEPTANCE_LOCAL_WRITES=1`及测试账号密码，使用新准备的、尚未付款的`fundingUi`场景。默认读取`.tmp/partial-correction-http.json`，可通过`PARTIAL_CORRECTION_FIXTURE`指定。

准备场景使用现有`project-packages-acceptance.mjs`，启用商城、结项、取消、订单清算、专项资金及专项冻结更正验收开关。所有凭据和账号属于隔离验收数据，不代表真实银行出款、退款或客户正式身份认证。
