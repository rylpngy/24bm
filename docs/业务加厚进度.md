# 业务加厚进度(D3–D14)

> 背景:后台页面"只有样式、看不到实际业务内容"。本轮按主流程顺序逐个把实体"加厚"——
> 不是改样式,而是补真实业务字段、推导业务指标、打通跨单据数据流,并在前端可视、预览实证。

## 统一加厚闭环(每站都走一遍)

1. Flyway 迁移(`db/migration/V1xx`)新增列
2. 后端全栈扩模型:domain record → MyBatis Mapper(select/insert/update)→ DTO(Request/Response)→ ApplicationService(透传/兜底/推导)
3. 修测试:record/构造器加参(Python 括号匹配脚本批量追加)+ Mockito mock 调用对齐
4. `mvn test` 全绿(385)
5. 重建库 + `db/demo/V2xx` 灌真实演示数据(低版本迁移与 V200+ 种子乱序,需 drop/create 库)
6. 导出 OpenAPI(`scripts/export-backend-openapi.mjs`)+ orval 重生成(`pnpm --filter @24bid/api-client generate`)
7. 前端展示新字段
8. 预览(`preview_*`)截图核验真实数据

## 端到端互联(不再是孤立展示)

- **订单页**:抬头信息 → 物流信息 → 收货验收明细(D6+D10+D9 一屏可见)
- **发票页**:价税明细 → 三单匹配(金额+数量双维度)→ 付款执行记录(D7+D12+D14)
- **三单匹配数量维度**:发票对账层从收货单(D9)推导合格率与匹配结论(finance↔order 跨模块装配)
- **供应商库**:档案(主数据)+ 绩效考核(SRM)

## 工程化护栏(随加厚一并维护)

- orval `clean:true` 会清空 `controllers.ts` 桶 → 新增 `build-controllers-barrel.mjs` 并接入 `generate` 自动重建。
- 新增买方物流端点 `GET /buyer/deliveries`:登记进 HttpSecurityContractTests 控制器清单 + ArchUnit 冻结库(`archunit_frozen`)。
- finance↔order 跨模块(发票读收货单):ArchUnit 冻结库补 `infrastructure` 依赖(构造/字段/调用),改构造器签名会使旧冻结项失效、需补新签名项。
- 订单 `updateOrderDetails` / 物流 `updateSupplierDelivery` 用 `coalesce` 防只改单项时清空其余字段。
- 税额/合格率等指标统一在后端响应层推导,前后端口径一致。
