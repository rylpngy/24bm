# 跨年冻结付款更正

## 办理入口

采购方“发票付款 → 发票详情 → 跨年冻结付款更正 → 更正台账”。普通付款台账中的冻结原流水只标识“跨年冻结”，不能直接冲销。

1. 系统列出已纳入跨年度承接依据的正向付款，显示原付款凭据、原责任年度、办理时的承接年度和整笔金额。
2. 有冲销权限的经办人选择“申请更正”，填写更正凭据号、原因，随后按已发布流程填写审批字段并提交。
3. 发起人不能审批自己的申请。审批人在统一审批中心核对原发票、原付款、年度依据及更正凭据。审批前不改付款或预算金额；发起人可填写原因撤回。
4. 批准后新增一条完整反向付款流水，保留原流水。同步发票付款状态、合同里程碑、既有付款执行记录及预算更正口径；拒绝或撤回不改变资金。
5. 在更正详情查看流程历史、原流水、更正凭据和反向流水。补正后重新付款仍使用正常的已批准付款依据与金额校验；不能绕过付款审批。

## 年度口径

本模块是预算责任与付款登记的经审批更正，不是直接修改会计账或发起银行退款。更正凭据须由业务人员核实，真实退款等银行操作仍在资金系统办理。

例如原年付款 50 元，跨年度承接后该 50 元被冻结。更正批准后另记 -50 元，原年在“更正后口径”中的已付责任减少 50 元，办理时承接年度的未支付责任增加 50 元；整项目责任总额不变。原付款的金额、日期、经办人以及原承接审批快照均保留，不回填、不删除，也不将历史承接快照当作已经更正的原始凭据。

后续再次跨年承接时，以更正后的当前责任计算，不能再次冻结已冲销的原付款。原始记录和更正后统计可通过更正台账及审批快照对照追溯。

## 当前支持范围及保护

- 支持来源唯一、可核对且项目仍处于已批准状态的冻结付款整笔更正，不支持任意改金额或部分冲销。
- 关联合同已归档、项目已结项/终止、存在订单清算责任、在审立项变更或承接时不允许办理。已结项清算和跨年实物退款的复杂重开账不包含在本批范围内。
- 原付款已冲销、归属不唯一、冻结金额不足、历史付款状态/流水不一致或合同里程碑待核对时拒绝处理。
- 提交后付款、项目年度或里程碑变化，原审批不能继续生效，必须驳回后按最新依据重提。
- 相同提交编号与内容重试返回原申请；改内容拒绝。同一原付款不能重复在审或重复批准。
- 非预警模式仍校验恢复的承接年度额度；不足时审批、反向流水及里程碑变动一起回滚。原系统预算预警模式不主动切换。
- 更正在审时阻止采购执行归档。批准更正必须同时具备真实反向流水和独立审批证据，纳入项目 ZIP 的业务快照与流程历史。
- 已完成更正和原始依据受数据库保护，不能通过修改状态或删除记录消除历史。

## 技术及交付边界

新业务类型为 `frozen_payment_correction`，继续使用 Flowable 统一运行时。接口位于 `/api/v1/buyer/invoices/{invoice}/payment-ledger/corrections`，包括候选流水、分页台账、提交、撤回。服务层仍校验发票数据范围，HTTP 边界区分查看权限与 `buyer:payment:reverse` 权限。

V248 仅增加更正表、索引、保护触发器及预算统计视图，不更新旧业务行或旧迁移。应先在原库备份副本验迁，禁止修复原库 Flyway 历史或用验收库替换原数据。

本批基于 PR #141 的分次开票开发分支继续迭代。父 PR 未合并时，新 PR 采用依赖关系交付；GitHub Actions 账号额度问题不作为绕过检查或直接覆盖原系统的理由。专项资金独立台账、多来源分摊仍待后续开发。
