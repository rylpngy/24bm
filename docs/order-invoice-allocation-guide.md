# 无独立合同订单与逐票清算

## 本批范围

采购订单详情的“合同解除与订单清算”同时支持无独立合同的订单。无合同场景不伪造合同，不要求合同管理权限；有关联合同仍要求合同管理权限。双方协议原件、供应商确认、独立内部审批、财务凭证及结清检查均保留。

多张或分次历史发票不再直接拦截，改为逐张明确最终货款归属。系统展示发票号码、原金额、真实已付金额及未开票余额。所有归属均需填写，允许零金额，货款合计须等于实际保留数量乘清算单价；每项不得超原金额，补偿款另列。申请、供应商确认和审批使用不可变方案快照。

## 操作

1. 在采购订单详情展开清算台账，核对退换货及验收处置，上传清算协议原件。
2. 发起订单/合同清算，核对保留和终止数量、约定单价、补偿款；若显示逐票归属，为每张发票及未开票货款填写最终货款。
3. 供应商下载协议并同意，原发起人提交内部审批，由有权且独立的办理人审批。
4. 财务按“发票或款项归属”登记实际退款、补付款及最终发票/红冲核对原件。发票全额冲销时仍应登记零金额红冲核对凭证。未开票余额最终为零时不强制提供不存在的发票。
5. 每项净付款、最终发票/红冲或补偿凭证均核对完成后才能完成清算。订单有合同时同时归档合同；无合同时完成订单清算。后续按项目/分包结项流程生成归档包及释放预算余额。

例如原发票A已付600元、B未付300元，最终A归属300元、B归属300元：整体已付及最终金额均为600元，但仍须登记A退款300元及B补付款300元，不能因总额相同直接结清。

## 数据与边界

- 原始订单数量/金额、收货和不合格记录、发票及原付款流水不改写。清算新增归属及凭证来源，纳入业务快照、审计、预算净额、采购执行核验及归档。供应商不获取原始银行流水明细。
- 兼容历史单张全额发票及旧清算记录；历史凭证归属为空，不补造历史数据。
- 多合同订单、历史支付缺少真实流水、跨部门资金未拆分、跨年冻结支出、未核销不合格验收及在途货物仍需先核验，不自动猜测。
- 这是已有发票的清算能力，不是新增分次开票、税控红冲、真实银行支付/退款或财务记账。供应商普通开票入口继续使用既有全额开票规则；本批不声称完成这些外部能力。
- 预算继续保留预警模式；不使用验收库替换原系统，不向原系统导入测试业务数据。

## 验收要求

覆盖无合同清算、同单退款和补付相抵、未开票余额、零金额冲销凭证、错误来源/超额/重复凭证、旧单票兼容、真实供应商确认及独立流程审批，核验预算净额、原件下载和项目ZIP。正式发布前须完成原数据库副本迁移演练，并核对原表原列数据及原附件未变化。
