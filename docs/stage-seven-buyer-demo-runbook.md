# 阶段七采购方现场演示脚本

## 演示目标

本脚本用于现场演示采购方企业端在 Java 数据源下的询价比价闭环。演示范围是采购方主流程，不扩展商城、竞价、招标、AI、真实支付或 ERP 集成。

演示结论要讲清楚三件事：
- 系统已经不是静态页面，而是可以连 Java 后端完成真实业务写入。
- 采购方主流程已经覆盖“需求申请到付款登记”的完整链路。
- 7 个采购方主流程动作均真实点击成功，动作反馈来自 Java 数据刷新和页面状态回显。

## 准备动作

1. 确认本地服务可访问：
   - 前端：`http://localhost:3000/`
   - 后端健康检查：`http://localhost:8080/api/v1/health`
2. 重置 Java 演示数据并跑一遍自动验收：
   - `node scripts/stage-seven-real-action-click-check.mjs`
3. 确认验收产物：
   - `docs/artifacts/stage-seven-java-real-action-click-result.json`
   - 期望结果：`failed` 为 `0`，7 个动作的 `attemptedRealClick` 和 `successVisible` 都为 `true`。
4. 现场入口：
   - `http://localhost:3000/?role=buyer&module=demands`
5. 数据来源说明：
   - 页面右上角应显示 `Java 数据源`。
   - 本轮演示样本来自 `V120__stage_seven_real_action_demo_seed.sql`。

## 开场话术

这套演示先不讲平台所有远期规划，而是聚焦采购方最核心的询价比价闭环。我们从采购需求开始，经过审批、询价、报价比选、定标、订单、收货，最后到发票付款状态登记。每一步都不是静态按钮，都会通过 Java API 写入或刷新业务状态。

演示时可以强调：目前真实支付、电子签章、ERP 深度集成还没有接入，付款动作只登记付款状态，不触发真实资金流。

## 逐页讲解

### 1. 采购需求

开场话术：采购从内部需求开始，需求有预算、物料明细、附件和审批状态。这里演示的是一条可提交审批的草稿需求。

演示点击：点击 `提交审批`。

成功反馈：页面出现 `采购需求已提交审批`。

讲解重点：提交后需求进入审批中，系统保留“不能重复提交”的业务边界。采购方的主流程不是从 RFQ 开始，而是从内部需求合规开始。

### 2. 审批中心

开场话术：审批中心承接需求审批、准入审批和定标审批。本次先演示需求审批通过。

演示点击：勾选确认上下文后点击 `通过审批`。

成功反馈：页面出现 `需求审批已通过`。

讲解重点：审批动作会真实更新后端审批任务和需求状态。审批通过后，需求才具备进入询价的资格。

### 3. 创建询价

开场话术：审批通过的需求可以邀请已准入供应商，形成 RFQ。

演示点击：回到采购需求页，点击 `创建询价`。

成功反馈：页面出现 `询价已创建`。

讲解重点：RFQ 会关联需求和供应商邀请。本阶段先演示核心流转，不展开复杂招标、竞价轮次和专家评审。

### 4. 报价对比和定标审批

开场话术：供应商报价后，采购方进入报价对比页。这里重点看价格、交期、税率和推荐定标理由。

演示点击：点击 `提交定标审批`。

成功反馈：页面出现 `定标审批已提交`。

讲解重点：定标不是直接生成订单，仍需要审批。这个边界能体现采购合规链路。

### 5. 生成采购订单

开场话术：当定标审批已通过，系统开放生成采购订单。

演示点击：点击 `生成采购订单`。

成功反馈：页面出现 `订单已生成`。

讲解重点：订单继承 RFQ、供应商和金额上下文，后续进入供应商确认、发货、收货验收。

### 6. 收货验收

开场话术：供应商发货后，采购方在收货验收页登记验收结果。

演示点击：点击 `登记收货`。

成功反馈：页面出现 `收货验收已登记`。

讲解重点：收货是发票付款前的关键节点。演示样本中物流状态和订单状态已经满足收货条件。

### 7. 发票付款

开场话术：收货后进入发票付款页面，系统展示三单匹配、对账、差异处理和付款状态。

演示点击：点击 `登记付款`。

成功反馈：页面出现 `登记付款完成`。

讲解重点：当前只登记付款状态，不接真实支付。付款登记会刷新发票状态，为后续财务深化、付款批次和归档审计打基础。

## 异常兜底

如果现场页面没有出现预期按钮，先执行：

```bash
node scripts/stage-seven-real-action-click-check.mjs
```

这个脚本会先应用 `V120__stage_seven_real_action_demo_seed.sql`，再用 Chrome CDP 真实点击 7 个动作，并重新生成 `docs/artifacts/stage-seven-java-real-action-click-result.json`。

如果页面提示加载失败，按顺序检查：
- `curl -s http://localhost:8080/api/v1/health`
- `curl -I http://localhost:3000/`
- 浏览器地址是否为 `http://localhost:3000/?role=buyer&module=demands`
- 页面是否显示 `Java 数据源`

如果某个动作已经点过，重新执行真实点击脚本即可重置本地 stage7 演示样本。
