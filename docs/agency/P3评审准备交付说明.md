# P3第一项：评审轮次与规则冻结

日期：2026年11月9日。本轮在24Bid隔离研发工作区完成P3的首个闭环：建立评审准备轮次、绑定采购文件定稿、配置人员职责、逐项核对规则、冻结不可覆盖的准备版本。P3正式评分及现场执行仍在后续范围内；没有部署到原24Bid或生产系统。

## 使用方式

进入已通过建档且没有待审重要变更的采购包，打开“采购执行工作台 → 评审准备”。需要评审读取和保密权限，另需采购文件及附件读取权限。维护、冻结分别受独立权限控制。

1. 选择已审批采购文件的精确版本，填写轮次名称、评审方法、规则版本、适用依据、计划时间地点及同分处理依据。
2. 从已获采购包授权的有效账号中配置承担职责的人员；项目组织、评审、组长、资格审查、符合性审查、采购人代表及监督职责分别记录。会前准备名单不会自动带入，也不自动授予评分权限。
3. 按定稿逐项录入文件原文规则、位置及系统配置，包括事项、适用对象、审查或评分阶段、分值、权重、计算规则、依据要求和小数规则。两侧独立编辑；可明确点击“以本项原文填入配置”，之后仍须人工勾选本项已核对。
4. 保存草稿后查看阻断项和差异表。原文与配置不一致、权重不符、缺少职责或逐项确认时不能冻结；不自动修正原文录入值。
5. 由有冻结权限的项目人员核对全部适用规则、人员及配置，填写确认依据，再明确确认冻结。冻结指准备配置锁定，不代表已正式开启响应材料、已开始评分或已形成评审结果。
6. 冻结后可导出快照与哈希。纠错采用填写原因后作废、重新建立轮次的方式；不直接改写冻结内容。作废轮次仍保留冻结快照及历史原因。

## 状态、范围与保护

- 状态为准备草稿、配置已冻结、已作废。每包最多50个保留轮次，每轮最多30名人员、100条规则；本阶段没有正式执行状态。
- 草稿维护校验乐观版本并记录原因，新增和修订支持幂等。后台版本变化时保留未保存内容，阻止覆盖；冻结确认绑定当时版本，版本变化后必须重新勾选。编辑内容未保存时不能直接打开其他草稿覆盖本地编辑器。
- 账号须为当前租户有效账号，且为采购包负责人、创建人或已授权成员。职责配置不自动扩大项目范围、不创建专家账号、不调用外部专家库。
- 资格与符合性审查分别要求相应职责，不能仅因某账号是评审成员便视为具有全部审查职责。不硬编码所有采购方式的委员会人数。
- 冻结只接受当前已审批采购文件版本；采购文件公共基础或确认需求变化会阻止冻结。冻结时读取实际文件字节验证哈希，保存源文件、人员姓名与职责、全部规则、计划信息、核对人、说明和时间。
- 冻结后基础变化提示重新复核，原快照保持不变。新轮次不继承旧轮次的冻结状态，也不隐式作废其他轮次。
- 创建人和普通采购管理权限不能绕过评审保密权限；读取工作区和导出快照均执行相同的租户、采购包、评审、文件读取和保密权限检查。
- 所有写入口复用建档通过守卫和采购包事务锁。配置修订、冻结、作废记录业务事件及审计；并发相同请求只冻结一次。

## 当前规则能力的边界

本阶段校验用户录入的数据，不能自动证明已覆盖Word中的全部规则。正式使用前仍需业务负责人基于实际采购文件核对适用规则与样例。技术验收使用合成规则，不作真实采购业务或法规适用认证。

支持通过/不通过审查项，以及零起分、正满分的技术或商务评分项。当前评分公式仅配置“原始分/满分×权重”，权重使用BigDecimal精确合计100；数值最多6位小数，保留位数0～6，支持四舍五入、半偶舍入和向零截断。此处只定义及验证计算规则，尚未接入评分计算。其他公式、非零最低分、价格公式及特殊制度规则尚未支持，应保留为后续实现，不能用近似配置替代。

六种采购方式只完成准备阶段的方法兼容性守卫：公开/邀请招标可配置综合评分或最低评标价，磋商为综合评分，谈判、询价、单一来源分别保留价格规则或协商准备。非综合评分配置拒绝技术商务综合评分项。这不代表六种现场程序已实现或已通过业务样例验收。

## 接口与迁移

新增V274迁移保存轮次、配置、冻结快照及哈希，已在独立数据库应用。运行服务导出的[P3接口契约](p3-rounds-openapi.json)包含6个操作、5条路径、16个引用模型。

接口前缀：`/api/v1/buyer/agency/evaluation/packages/{pkg}/rounds`。

| 方法及路径 | 用途 |
| --- | --- |
| GET / | 读取轮次、差异、阻断项和定稿来源 |
| POST / | 建立准备草稿 |
| PUT /{id} | 按版本修订草稿 |
| POST /{id}/freeze | 明确复核后冻结准备配置 |
| POST /{id}/void | 作废轮次并保留历史 |
| GET /{id}/snapshot | 导出规范快照文本及可核验哈希 |

实现：[轮次服务](../../backend-java/src/main/java/com/procurement/agency/application/AgencyEvaluationService.java)、[规则校验](../../backend-java/src/main/java/com/procurement/agency/application/AgencyEvaluationRules.java)、[评审准备面板](../../apps/tenant-portal/src/features/agency/agency-evaluation-panel.tsx)。新增权限点已纳入可分配权限目录。

```sh
python3 scripts/p3-rounds-run-smoke.py
node scripts/p3-rounds-browser-smoke.mjs
pnpm test
pnpm --filter @24bid/tenant-portal build
```

后端在`backend-java`目录使用Java21执行`mvn -q test`。HTTP脚本仅允许独立18080服务和procurement_agency_p0库，创建专用合成租户，不操作生产数据。
