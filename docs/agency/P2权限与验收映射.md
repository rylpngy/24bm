# P2 权限与验收映射

所有执行接口首先校验租户、底座代理权限及采购包范围。业务写入须建档已通过、半流程且没有待审重要变更，随后锁包重新检查。公司模板和公司计划模板使用公司配置权限；项目模板必须属于当前包。

| 权限后缀（前缀buyer:agency:） | 用途 |
| --- | --- |
| demand:read / demand:manage | 查看需求与来源 / 维护需求及发起提取 |
| template:manage | 维护公司或本包模板、提交发布、启停；公司模板使用仍要求当前已发布版 |
| document:read / document:manage | 查看、检索历史 / 维护章节、同步公共基线、生成或登记候选 |
| document:submit | 提交当前候选版本送审，仍需编制写范围；审批办理权由统一引擎控制 |
| document:exception | 在完整性缺章时说明例外；维护公告适用性依据；不能绕过基线和一致性问题 |
| publication:manage | 登记已经实际发生的外部人工发布 |
| participation:read / participation:manage | 查看 / 维护内部参与记录，不产生资格或准入结论 |
| plan:read / plan:manage | 查看 / 调整节点、实际结果及依赖 |
| plan:configure | 维护公司按采购方式区分的半流程节点模板 |
| plan:legal | 维护、取消法定时限及例外依据 |
| preparation:read / preparation:manage | 查看概要 / 维护会前准备 |
| preparation:confidential | 查看及维护委员会、抽取记录和保密凭证，写入同时要求preparation:manage |

封存资料引用另需 `file:read` 及文件范围；生成DOCX还需 `file:manage`，字节下载另需 `file:download`。来源在每次引用、任务完成、整稿登记及下载时重新校验。历史文件检索先按授权项目过滤，再检查文件范围。结构化需求不从受限材料直接向项目读者扩散。

| 需求 | 本次证据与覆盖边界 |
| --- | --- |
| DEC-05、DOC-01～03、AT-04 | 多来源及冲突、人工确认/修订、来源位置、真实异步提取、失败重试与人工回退；AI/OCR/复杂表格未验收 |
| DEC-06、DOC-04、WFL-03 | 章节快照、合成候选、当前版本送审、缺章授权例外；不逐章固定审批。采购方式专有规则待P3 |
| DEC-07、AT-05 | 真实Flowable整稿与公告分别通过、通常发布就绪、修改后新基线不继承审批、人工发布凭证及精确版本 |
| DEC-08、8.5～8.6、AT-06 | 整稿DOCX人工复核、哈希与版本、不可变下载、合成样例渲染；Office线上及复杂实际文档往返未验收 |
| 9.1 | 公司模板审批与版本、项目自有范围、历史已审稿按权限检索引用；结构化来源日期、制度版本和公司库申请已补齐，见P2补充交付说明 |
| DEC-09、PART-01～05 | 内部台账、获取与提交状态分开、风险不等于资格；手工及CSV/XLSX预览确认批量追加，见P2批量导入交付说明 |
| PLAN-01～03 | 初始化、公司节点模板新版本只影响新项目、负责人、依赖DAG、真实完成、逾期不自动完成、自定义节点及下游提示 |
| PLAN-04～05 | 站内分级、升级、去重、重试及入库/已读观测已补齐；短信尚未配置 |
| PLAN-06 | 单独法定截止/依据与专有权限，普通计划调整不能任意取消法定时限；不预置统一法定天数 |
| 12.2的准备部分 | 保密组建/抽取记录、场地起止及用途、重叠拒绝相邻允许；正式评审人员职责、签到表单与开启保密属于后续P3 |
| AT-19～20的执行部分 | 跨租户/项目隔离、历史检索范围、受限材料、审批冻结、版本冲突、任务失败与中断恢复；不代替P3评分/报价及P4支付验收 |

实际检查名称以 [p2-http-smoke.json](evidence/p2-http-smoke.json) 和 [p2-browser-smoke.json](evidence/p2-browser-smoke.json) 为准。未执行项保持待验收，不由同一小节中某一检查通过推定全部需求完成。
