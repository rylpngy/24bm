# P3第五项：线下最后报价发起、接收与确认

2026年11月9日。基于24Bid现有身份、附件、评审轮次及权限体系，新增谈判、磋商的线下最后报价工作区。适用于一期半流程记录，不代表供应商在线递交、身份核验、电子签署或实际通知发送；未部署生产。

## 已实现闭环

在“评审准备 → 独立评审任务 → 线下最后报价（谈判/磋商）”操作。仅冻结的组织人员或组长可访问，另需独立的最后报价读取及管理权限。公开招标、邀请招标、询价、单一来源页面不显示该入口，服务端拒绝这些方式调用。普通评审人即使拥有通配权限，也不能绕过冻结职责读取该工作区或原文。

1. 发起前，采购包及轮次基线须有效、材料已正式开启、已按定稿规则开放评审或专业协商阶段，且无待审更正。从该阶段对象中明确选择参与者；未进入者逐家填写依据。人工核对最终需求、最终响应条件和发起通知的脱敏封存凭证后，锁定参与范围、实际发起时间和截止时间。实际发起不得早于本任务真实开启时间，截止须晚于发起。本任务只保留一次发起，不直接重置截止或追加竞价轮次。
2. 逐家登记原始最后报价、采购包币种、实际接收时点、原件类型、最终响应来源及补录依据。系统登记时间单独保存。支持线下事后补录，截止后登记必须有接收时点依据；实际逾期仍按逾期记录，不因补录原因而转为有效。金额保持十进制字符串和两位以内精度，允许零元，不预设必须低于初次报价。
3. 最终响应及报价副本使用专用`final_quote_material`受限类别，通过现有上传票据、字节检查、封存及SHA256校验。普通附件接口不能创建该类别或追加其版本。确认前，包括创建人在内均不能下载原文；该材料不能成为普通需求提取、编制发布稿或通用档案快照来源。接收有误可先撤回，再追加新登记；旧金额、来源、原件信息、撤回原因和文件保留。
4. 截止后，组织人员必须对锁定范围逐家选择“有效最后报价”“未提交”“逾期”或“排除”，逐家填写处理依据，并提交脱敏的确认及异常处理凭证。有效报价须引用当前按时接收登记及已封存实际字节；未上传、哈希不一致、漏对象、把已接收者记为未提交、把逾期记为有效均阻断。接收版本及材料指纹变化会使旧人工确认失效，保留页面未提交的判断和说明。
5. 确认后记录锁定，不再接收、撤回或覆盖。仅有权组织人员且具备响应读取、文件下载权限时，可下载确认为有效的精确材料版本。未提交、逾期和排除对象不产生有效最后报价金额，不复制初次报价，也不开放其副本。初次报价台账原值保持独立。

所有写入使用采购包事务锁、租户与项目范围、冻结职责、现行基线及幂等保护。最后报价发起后，本任务已提交的独立意见不再支持直接发起更正；需按异常程序另行组织。业务事件记录范围或结果指纹，不把价格自动推送到通用事件内容。

## 后续门槛

本轮完成最后报价记录闭环，不等于谈判或磋商全流程完成。逐家谈判/磋商沟通、需求变更的有权确认与逐家送达、缺失报价后的正式继续或终止决定、专有推荐规则与报告仍需推进。页面记录处理依据，不因一次确认自动恢复评审或触发成交推荐。

下一项接入冻结价格规则、十进制计算明细和适用价格来源；谈判/磋商不得在缺少已确认最后报价时静默使用首次报价。最后报价的后续修正、政策适用审批、价格评分、同分处理及汇总须独立受控实现，不将本次原始最后报价直接视为政策评审价、成交价或合同金额。实际采购文件、业务适用规则和复杂模板继续保留业务样例验收门槛。
