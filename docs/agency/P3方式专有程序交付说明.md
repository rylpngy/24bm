# P3邀请、询价与单一来源专有程序

2026年11月9日，连续研发第13至15项的本轮技术交付，保持一期半流程，不上线生产。

邀请招标记录实际名单来源、形成／外部抽取、资格核验或预审适用依据，以及逐家通知时点、接收人、送达或拒绝情况和凭证。系统不随机指定供应商，不默认一律资格预审；正式开启必须有本轮准确邀请与实际送达依据，且开启时间不得早于送达。开启后不允许倒改邀请记录，后续资格、符合性和评审职责仍分别执行；本台账不限制供应商获取采购文件。

询价逐家记录一次报价有效性、缺失与异常处置，绑定精确当前报价链尾。遗漏对象不能确认，待处置事项阻断计算。每个对象仍只允许一条原始报价，随后只追加有据修正／政策层，原金额不改；变更报价层会使既有有效性与价格快照失效，须重新核对。无效／缺失对象不能纳入价格计算，不能通过排除未处置异常绕过整体阻断。价格比较不生成技术商务分、排名或成交；不开放谈判／磋商最后报价入口。

单一来源在开启前记录适用理由、实际论证审批和公示的适用性。适用时必须有实际凭证，不适用时必须说明依据，不能把未办理标为已公示。协商记录绑定本轮唯一供应商和真正承担专业评审／采购人代表职责的冻结人员，保留实际时点、价格合理性资料和分析、质量保障、协商金额及线下确认来源。币种一致，金额受已明确限价保护；不强制三家、不产生竞争性评分或排名，协商记录也不等同采购人最终确认。

三条路径按轮次保留不可变追加历史，使用项目范围、保密与专有程序权限，以及冻结组织职责。新权限为`buyer:agency:procedure:read/manage`。暂停及基线变化继续阻断写入。V286保留此前已开启邀请／单一来源及已有询价价格计算的显式历史路径，不补造历史。界面位于评审准备的冻结轮次内，按实际方式展示，历史使用业务字段标签，不显示传输幂等键。

实际技术验收：后端专项93项、前端专项4项，生产构建通过。真实HTTP分别通过邀请2组、询价2组、单一来源1组，使用三个独立合成公司、实际PostgreSQL/Flowable/MinIO及真实DOCX编制审批。覆盖开启前置、名单来源、非默认预审、邀请送达、一次原价保护、有效性与修正重核、价格比较与历史失效、唯一协商供应商及专业职责、禁止跨方式最后报价。各场景仍使用技术样例，不等同真实制度、法定人数、真实企业材料或完整六方式业务验收。
