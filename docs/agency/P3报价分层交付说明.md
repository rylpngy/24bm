# P3第四项：人工初次报价分层台账

2026年11月9日。本轮实现原始初次报价、经人工核对的修正报价和政策评审价格的独立记录。仍为隔离研发及合成数据技术验收，未部署生产；六方式专有程序、最后报价、价格公式及排名尚未完成。

## 使用

在已正式开启、基线仍有效的独立评审任务中，冻结的组织人员或组长可展开“人工报价分层记录”。另需报价读取权限；追加还需报价管理权限。普通评审人即使拥有通配权限，也不能越过冻结职责读取此台账。

选择开启对象、价格层、金额、币种、已脱敏的项目可见封存核对依据，填写理由并明确确认。每个对象只能首次建立原始报价；后续只能引用当前链尾追加修正或政策评审价。历史记录没有覆盖或删除入口。

原始报价始终保留。政策价不会改写修正价、原始价或合同金额；新增修正后当前政策价置空，必须按新基础重新核对，旧政策价格仍在历史中。没有政策价时不自动用其他价格冒充已确认政策结果。

金额用BigDecimal及numeric(20,2)存储，非负、整数最多18位、小数最多2位，不自动舍入。金额响应按十进制字符串输出，避免浏览器浮点丢失大金额精度。零金额与未填写区分；同一链不能混币种。页面基于链尾版本确认，后台追加后旧确认失效，并保留未提交内容。

所有写入执行租户、项目、有效冻结人员、正式开启及基线守卫，使用采购包事务锁、当前前驱校验和幂等键。每条记录保存核对文件版本及实际字节哈希、原因和记录人；通用业务事件只记录层类型和依据指纹，不自动暴露价格值。

## 保留范围

本轮是人工核对台账，不是政策适用认定或价格计算审批。来源目前使用项目可共享的脱敏核对凭证；原始响应报价明细的专有提取与直接绑定仍需后续实现，不应将未授权的敏感报价正文误传为普通项目附件。

不提供成交/合同金额修改，不自动排名、价格打分或汇总。谈判、磋商的最后报价须由专有发起、截止、最终响应及确认流程建立，不能用本台账的初次报价替代。下一项继续这些方式差异、冻结价格规则与十进制计算明细。实际采购规则及复杂模板仍须业务样例复核。
