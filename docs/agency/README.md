## 已实现范围

- 所属项目标签可搜索、新建和复用；采购包独立编号和维护；批量建档一次生成1至20个包，共同字段带入，批量请求有幂等控制。
- 六组档案字段：基础分类、采购人与联系人快照、委托与服务范围、项目组织、收费约定、附件及补充资料。草稿允许缺项，洽谈阶段可提交，委托协议可后补。未知金额与零元区分，金额精确保存。
- 一名有效主负责人，支持协作编辑、只读成员、文件编制人和办公室对接；成员变更保留历史。租户、本人创建、项目成员和授权部门/公司范围在服务端执行，列表按相同范围过滤。
- 首次提交按公司和业务年度分配四位流水，跨月份和类别共用计数；重试、撤回和退回重提保留编号。编号格式及分类字典可配置，规则更新不改旧编号；9999拒绝溢出并向具备编号配置权限的有效用户发送去重站内告警。
- 建档和重大变更分别接入统一Flowable。审批冻结档案与附件快照，在审禁止修改；不可自审。重要变更通过前保留原值，通过后受控生效。采购包版本冲突返回409。
- 分类附件独立版本上传，字节、哈希及基础内容检查后封存；封存版本不可覆盖，新版本追加。可取消未完成版本，登记成功但封存失败可重试封存。送审只引用每份附件当时最新的有效封存版本，历史审批可下载原版本。
- 文件级受限范围和独立下载权限；成功读取下载字节记录审计。上传限制10MB，Office解压限制60MB，拒绝路径穿越、宏、嵌入程序、EICAR测试签名及部分活动PDF内容。核心状态、审批、成员、配置和文件操作均有审计或不可变修订历史。
- 建档未通过或有待审重大变更时，下游统一守卫拒绝操作。全流程模式在服务端拒绝创建，界面标为规划中。业务、档案、费用三个状态独立持久化，本阶段为各自初始状态。

## 入口与代码

本地前端：[招标代理项目库](http://127.0.0.1:15173/?module=agency)。本地后端为18080，独立数据库15432、MinIO19020/19021。前端进入普通租户门户的“招标代理”；当前不是鲁东POC专用入口。需要有效登录和相应业务权限。

后端位于 [agency业务域](../../backend-java/src/main/java/com/procurement/agency)，前端位于 [agency页面](../../apps/tenant-portal/src/features/agency)，API客户端位于 [agency.ts](../../packages/api-client/src/agency.ts)。复用现有身份、组织、附件、审计、通知与流程运行时，没有另建技术栈或第二套审批引擎。

接口契约为 [p1-openapi.json](p1-openapi.json)，从本次运行服务导出并提取19项操作及其38个关联Schema；operationId采用agency前缀。上传票据、字节上传和下载继续使用已有附件接口，ownerType为agency_file_version。

## 使用前配置

在“团队与权限”分配招标代理权限点和数据范围；在组织中维护有效部门及人员。进入“流程引擎”分别创建并发布“代理采购包建档”和“代理采购包重要变更”，配置实际审核人；审核人与发起人须分离。缺少已发布流程时提交会失败，数据库事务回滚，不会产生假审批或保留失败分配的编号。

日常操作为新建所属项目与采购包、保存草稿、补齐提交字段、上传并封存适用资料、提交建档审批、到智能审批办理。审核通过前仅维护建档资料。审核通过后普通信息可修订，预算、主体、采购方式等重要信息用“提交重要变更”；双方过程保留版本。费用约定当前仅存档，不在P1自动核算应收。
