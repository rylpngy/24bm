## 已实现业务

| 环节 | 当前行为 |
| --- | --- |
| 资料与需求 | 一次选择1至10份已封存来源版本，异步提取 TXT、DOCX 中明确的标准字段文本；每条记录来源版本及位置。候选初始为待确认或冲突，人工确认、修订、替代；不同已确认值不能并存。受限资料须先形成项目可见的脱敏需求版本。 |
| 模板治理 | 按名称、采购方式、标的、制度、地区、说明检索。公司模板每版章节不可覆盖，经独立审批发布；本包自有模板只在本包使用。停用阻止新引用，已引用稿件保留快照。来源依据用 sourceNote 留存，需人工维护。 |
| 分章编制 | 当前以标题和纯文本段落编制，支持排序、增补可选章节、必需章节检查和公共变量。采购文件与公告分别维护草稿和公共时间地点要素，可人工同步公告章节。公共字段或已确认需求变化，旧基线明确失效。 |
| Word 文件 | 按当前章节顺序异步生成真实可编辑 DOCX，保存字节哈希及来源快照，任务失败可见并可重试。任务输入过期时不挂入当前稿。支持下载当前或历史候选稿、本地编辑、上传封存 DOCX，经明确人工复核登记整份候选；不承诺自动反向拆章。 |
| 独立审批 | 完整采购文件、公告或邀请、公司模板使用不同 Flowable 业务类型。送审冻结实际文件、哈希、章节、公共字段与表单，发起人不能自审。支持退回、撤回重提，在审不能改稿；改稿或同步后须新候选和新审批。 |
| 例外与一致性 | 仅缺少必需章节内容可由具备独立例外权限者说明后送审，例外与流程实例留档，获批后可继续发布。公共字段过期、未解析变量、整稿公告要素不一致必须先处理，不能用完整性例外绕过。 |
| 人工发布 | 通常要求整稿与适用公告当前版本均已批准。公告不适用须有权限、说明和封存依据；不伪造公告通过记录。登记实际平台、已发生时间、有效链接或凭证，以及精确审批版本，幂等保存；系统不调用外部平台发布。 |
| 历史资料 | 在授权项目范围内检索已审采购稿。结构化稿件可复制条款到目标草稿，带入目标最新公共基线并记录引用说明；旧项目字面值须人工复核。整份上传的历史稿下载复核后重新上传。 |
| 内部参与台账 | 主体、联系人、来源、获取文件情况、递交响应情况、待核实风险和凭证分别保存并有版本。状态不接受资格合格或准入结论，不构成报名、缴费或投标门槛。 |
| 项目计划 | 建档通过后初始化；公司可按六种采购方式维护版本化节点及依赖模板，只影响以后首次初始化的项目。支持自定义节点、负责人、起止时间、依赖与循环检查、完成结果、调整原因、取消或不适用。逾期由真实时间计算，时间到期不自动完成；完成时间补记说明时保持不变。 |
| 期限与提醒 | 法定截止与内部计划截止分别保存，调整或取消法定截止受独立权限及依据控制。当前提供默认24小时临近、逾期站内提醒，按项目/节点/接收人/事件版本/级别去重；失败下次轮询重试，已读状态复用底座。 |
| 会前准备 | 记录场地起止时间、用途、材料、委员会组建和外部抽取结果及凭证。同租户同名称场地的重叠时段拒绝，相邻时段允许，内部预订使用事务锁处理并发。敏感人员与抽取资料独立控制；不宣称对接官方专家库或完成外部场地预约。 |

## 页面、接口与配置

入口：[招标代理项目库](http://127.0.0.1:15173/?module=agency)。进入已通过建档的采购包，下方显示“采购执行工作台”。重要变更审核中仍可查阅，暂停执行写入。文件在上方“分类附件与不可变版本”上传、检查并封存，再在工作台选择精确资料版本。

在流程引擎分别发布 `agency_template_publication`、`agency_purchase_document`、`agency_announcement` 定义，配置实际审批人。没有已发布流程时拒绝提交，不生成假审批。动态表单继续使用底座表单组件，具体审批节点由公司配置。

权限点在“团队与权限”分配，均仍需采购包写范围及底座 `buyer:agency:manage`。只读成员不会因单个执行权限取得写范围。详见 [P2权限与验收映射](P2权限与验收映射.md)。

后端代码：[执行服务](../../backend-java/src/main/java/com/procurement/agency/application/AgencyExecutionService.java)；前端：[执行工作台](../../apps/tenant-portal/src/features/agency/agency-execution-panel.tsx)；客户端：[agency-execution.ts](../../packages/api-client/src/agency-execution.ts)。接口前缀 `/api/v1/buyer/agency/execution`，33项操作、55个关联 Schema，均从运行后端提取到 [p2-openapi.json](p2-openapi.json)。附件上传及下载沿用原有附件接口，不新增第二套存储。

## 保留门槛与待补内容

- AI和Office在线编辑继续关闭。没有调用外部模型，也没有宣称完成AI推荐、语义一致性或在线协作。当前已验证确定性提取、手工检索/编制和整份Word回退；模型提示注入、推荐准确率及外部数据处理需另行验收。
- TXT/DOCX提取使用底座2MB、160段/4万字符的文本提取范围；PDF、OCR、扫描件和复杂表格不能承诺提取效果，允许保留原附件后人工维护。复杂富文本、原生表格和附件排版不属于本次章节纯文本合成器已验证范围。
- DOCX提供原生目录域与页码域；目录页码须在Word更新。本次技术样例没有复杂表格、合并单元格、复杂编号或客户字体的往返验收。正式使用复杂采购模板前仍需实际脱敏DOCX样例。
- 当前完整性检查由必需章节、公共变量、时间地点及公告一致性组成。采购方式/制度专有条款、结构化评分总分与采购项报价逐项检查、评审规则冻结和现场人员职责进入P3实现及业务样例复核；不把现有检查称为全面法律合规审查。
- 多级提醒策略、升级通知、站内入库/已读和重试观测已在补充交付中补齐；短信通道尚未配置。计划变更提示直接依赖节点，不自动重排后续日期。日程时区显示沿用浏览器时区。
- 模板结构化来源日期、政策版本、项目模板转公司库申请及参与台账批量导入已在补充交付补齐。专门人员表单打印/签署回传尚待补充。
- 正式评审任务、评分/报价/结果、标后收费及归档仍按P3/P4推进。生产Keycloak、性能、扫描服务和备份恢复仍需专项验证。
