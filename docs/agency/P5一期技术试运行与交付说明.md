[标后、收支及正式档案](P4标后收支与正式档案交付说明.md)覆盖采购人有权结果登记、公告与通知书、合同签署回传、质疑及有权暂停恢复、费用核定与事实流水、专家隐私、所属项目汇总、办公室待办、正式快照和按文件权限导出。业务、档案、费用独立办理，办结后可继续收付款和补档。相同收费约定、实际触发节点及付款收款主体不能通过换一个请求幂等键重复计费。

三个新增审批类型 `agency_evaluation_report`、`agency_post_document`、`agency_finance_review` 已进入流程配置界面和统一引擎目录，支持动态表单、独立审核及业务记录回链。需在实际公司发布相应流程并授予合适人员，不能把合成验收中的测试审批人当作生产默认值。

## 运行与复验

工作区为24Bid底座的隔离分支 `codex/24bm-agency`。原24Bid目录保持不变；未提交、合并或部署生产。本地技术环境前端15173、后端18080、PostgreSQL15432、MinIO19020／19021，避免占用原系统端口。

配置既有私有 `.p0/runtime.env` 后，执行 `python3 scripts/p0-run-backend.py` 启动隔离后端；前端使用 `pnpm --filter @24bid/tenant-portal dev --host 127.0.0.1 --port 15173`。运行密钥由本机私有配置读取，不复制到文档或命令输出。

执行 `python3 scripts/p5-continuous-run.py` 重新建立三个合成公司并顺序运行推荐、标后、费用、档案、权限、独立审核、办公室导出及浏览器验证；执行 `python3 scripts/p5-seven-run.py` 验证另外四条方法路径。复验会新建合成租户并配置其真实测试工作流，不用于真实项目自动审批。后续可执行 `node scripts/p5-workflow-entry-smoke.mjs`、`node scripts/p5-process-config-browser.mjs` 核对流程入口，`node scripts/p5-read-benchmark.mjs` 和 `python3 scripts/p5-restore-drill.py` 运行本地只读观察及数据库恢复。

后端检查使用Java21：`mvn -q -f backend-java/pom.xml -s backend-java/.mvn/settings.xml test`；前端使用 `pnpm exec vitest run` 和 `pnpm --filter @24bid/tenant-portal build`。数据库已验证迁移至V294，已应用迁移不修改；后续变更继续追加迁移。启动前应先复核实际公司流程定义、角色及项目／文件授权。
