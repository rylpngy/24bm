# P3第三项：受控材料接收、正式开启与共享阶段条件

日期：2026年11月9日。本轮接续[本人独立意见与受控更正](P3独立评审交付说明.md)，完成材料接收至正式开启，以及资格、符合性、评审意见之间的基础阶段控制。实现仍在隔离研发工作区，未部署生产，不改动原24Bid。

## 使用流程

在已审批采购包的有效冻结轮次中，进入“评审准备 → 材料接收与正式开启”。普通附件仍按原项目范围共享，响应副本须使用本专用入口登记，不能先当作普通项目附件上传。

1. 冻结的组织人员或组长在获得接收权限后，按实际定稿填写截止、允许开启时间、有依据的对象门槛、材料清单、必需项和开启后的可读职责。职责不自动全选；计划先保存草稿，经人工确认后锁定。
2. 从内部参与台账选对象，登记每项材料的实际接收时间、纸质原件扫描/电子副本、实际来源和原件保管说明。导入账号不代表供应商身份，接收记录不等于资格、到场或有效响应结论。
3. 上传并通过现有安全检查和哈希封存。未正式开启前，有权接收人员只能在系统查看登记与封存状态，创建人、普通保密文件权限、通配管理员也不能通过原始附件接口下载内容。
4. 错误登记可填写原因后撤回，原件保留，再另建接收记录。实际接收晚于截止的材料不能直接纳入开启；截止后补录但实际按时接收的，必须填写核对依据，分别保留实际时间与服务器登记时间。
5. 有开启权限的接收人员明确选择对象，生成开启预览，检查缺件、未封存、迟到、对象门槛及尚未到达开启时间等阻断项。人数不足不能自动改变采购方式或降低已锁定门槛。
6. 核对线下实际开启记录、材料版本和职责范围，选择已脱敏的项目可见封存凭证，填写实际开启时间和说明，再明确确认。服务器重新核对预览指纹和每份实际文件字节，成功后形成不可覆盖的开启清单及SHA256。
7. 开启后仍须满足项目范围、响应内容读取权限、保密权限、冻结职责及该材料项明确配置的可读职责，才能下载精确版本。接收人/创建人不会自动取得内容读取权限；未选入开启清单或已撤回的文件不随其他文件开放。
8. 根据开启快照建立独立任务，系统校验对象、凭证与实际开启时间一致，并按冻结职责拆分个人阶段任务。

## 阶段条件

- 阶段为资格审查、符合性审查、评审或专业协商意见；实际采用哪些阶段由冻结规则中的事项决定，不自动编造缺失规则。公开/邀请招标的当前支持路径要求明确资格和符合性事项；其余方式按实际配置的审查事项顺序执行，不强制单一来源三家或竞争排名。
- 同一账号可承担多种明确职责，但分别建立阶段意见版本，避免要求一张意见表同时完成尚未开放的后阶段。本人只能读取和编辑自己的职责项。
- 首阶段根据开启快照开放；后阶段不会自动开始。前阶段所有承担职责的人员须全部提交，且不存在待审更正或新的更正草稿，组织人员才能核对进入对象。
- 核对页面仅显示是否存在不通过意见及进入候选对象，不展示个人分值和评语。存在不通过意见的对象不能直接进入；未进入后阶段的对象须逐一填写依据，不能静默删除。进入数量仍须满足已确认门槛。
- 有权人员明确确认后形成阶段处理记录，绑定前阶段个人版本及指纹、进入对象、未进入原因和依据文件。只允许进入对象填写本阶段意见，不能继续填写已被排除的对象。
- 同一阶段内继续复用本人独立提交与Flowable受控更正。后续阶段已经开放时，禁止直接更正上游意见，以免形成前后矛盾；跨阶段合法更正及完整暂停/重新组织机制仍需后续实现，不能后台改分。
- 当前不处理分歧表决、特殊审查或特殊制度的自动结论。存在不通过或其他不适配条件时阻止直接推进，由实际适用程序处理，不以共享门槛替代完整采购规则。

## 保密与不可变性

响应文件使用专用`response_material`类别和受限范围，只能由接收入口创建并绑定轮次、对象与材料项。通用新建附件入口不能创建此类别，通用新版本入口不能覆盖响应原件。原始上传、封存、元数据读取和下载均接入相同服务端守卫；开启与上传使用采购包事务锁串行校验。

未开启响应文件不能作为需求提取、采购整稿或其他通用编制来源，不能借发布稿放大可见范围；通用档案送审附件清单不自动带入这些材料。正式归档的受控纳入规则留待P4实现。

接收清单确认后不支持直接改截止、门槛或职责，开启后不能改写原接收记录。开启预览与实际确认之间，材料或选择变化会要求重新预览；确认时实际字节哈希不一致会整笔回滚，内容保持关闭。已开启文件也不会因权限撤销而继续对原用户开放。

保护针对经专用入口登记的响应副本。系统不自动识别被误传至普通项目附件的响应内容，也不把历史普通附件自动重分类；上线前需要梳理历史材料。开启和阶段处理凭证目前要求为已脱敏、可在项目范围共享的材料，不应把未授权的报价或技术正文作为普通凭证上传。

本轮记录人工确认的线下事件，不是加密电子响应文件的法定解密开标，不对接外部专家库、官方交易平台或可信时间服务，也不自动证明线下事件真实性。复杂真实Word、扫描件内容识别和电子签章仍未验收。

## 数据与历史迁移

新增V276迁移保存接收计划、接收登记、开启清单和阶段处理记录；为个人意见增加阶段标识及按阶段的唯一版本约束。已在独立库应用，历史迁移保持原校验。

原有无正式材料开启记录的个人任务标为历史阶段，只读保留原意见与指纹，不伪造开启或阶段记录。继续业务须明确建立新轮次及受控材料流程。旧客户端不能把多个职责阶段混在一次提交中；新界面按本人阶段选择读写。

上限：每轮20个材料项、每批1～30个明确对象，最多保留1200条接收历史；个人意见仍最多3000个对象与事项组合。单文件沿用10MB及原有安全检查。中断或检查失败的接收可撤回后重新登记，不覆盖原文件；专用入口不提供分片续传。

## 接口与代码

本轮新增8个材料操作和2个阶段操作。运行服务导出的[P3完整契约](p3-opening-openapi.json)现有24个操作、21条路径、67个引用模型。

材料前缀：`/api/v1/buyer/agency/evaluation/packages/{pkg}/rounds/{round}/materials`。

| 方法及路径 | 用途 |
| --- | --- |
| GET / | 按授权读取计划、接收记录与开启概要 |
| PUT /plan | 版本控制的计划草稿 |
| POST /plan/confirm | 人工核对并锁定清单与时间 |
| POST /receipts | 绑定轮次与对象的接收及上传准备 |
| POST /receipts/{id}/withdraw | 撤回错误接收，原件保留 |
| POST /preview | 开启预览、阻断项及材料指纹 |
| POST /open | 核对实际字节后正式开放精确版本 |
| GET /receipts/{id}/artifact | 下载已授权开启版本 |
