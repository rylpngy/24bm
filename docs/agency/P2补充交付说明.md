# P2补充：分级提醒与模板治理

日期：2026年11月8日。继续在 implementation 隔离工作区、codex/24bm-agency 分支开发，复用原身份、权限、Flowable、通知、审计与数据库。本次补齐上一轮P2保留项中的分级提醒、升级通知、站内送达观测、结构化模板来源和项目模板转公司库入口。原P2业务闭环保持可用，未部署生产。

## 分级提醒

公司计划模板的每个节点可配置提醒策略，新项目初始化时复制策略快照；既有项目不随公司模板变化。项目计划中展开“提醒策略与站内送达记录”，选择节点，修改策略并填写原因。节点切换与加载有保护，策略未加载前不能编辑；未保存修改在自动刷新时保留，冲突返回409。

- 临近和逾期各最多5级，临近1～720小时，逾期0～720小时，0表示到期；级别不能重复。可以分别清空，也可以关闭提醒，保留原策略数值。
- 可选择有项目计划查看权限的有效升级接收人，配置逾期后多少小时升级。项目覆盖策略的升级人须与负责人不同；公司模板将升级人设成未来项目负责人时，不另发给同一人一条升级提醒。
- 默认策略仍为提前24小时和到期后提醒。未配置策略的旧项目保持原通知去重标识，部署新版本不会因此重发默认通知。
- 延迟扫描只发送当前级别，不补发所有已错过级别。临近取当前最接近的已到达级别，逾期取已到达的最高级别，升级另行判断。每个节点/版本的通知数量由有限级别约束，不连续无上限催办。
- 去重标识包含租户、节点、节点版本、策略版本、接收人及级别。节点或策略改动形成新事件；已发送记录保留，待发旧版本取消。
- 法定截止与内部计划截止仍分开维护，提醒取较早者，不自动改写任何期限或完成节点。重要变更审核中暂停待发提醒，审核结束后重新核对，不因暂停永久丢失提醒。

## 送达、重试与权限

新增持久化待发记录。创建待发记录与通知发送分开事务；实际站内通知写入和“已入库”结果在同一事务完成，避免通知写入失败却显示成功。发送前锁包及待发记录，再次检查节点/策略版本、当前期限、当前级别、接收人、账号有效状态及项目计划查看权限。

失败显示固定错误说明、累计尝试次数和下一次重试时间，自动退避从30秒逐步增加至最多1小时；可由有项目计划维护权限者立即重试。重试复用原通知标识，已入库通知只核对结果，不新增一条。扫描使用按ID分页，避免前100条已处理节点长期占用扫描窗口。

页面分别显示站内入库时间与已读时间。只读人员仅可查询发给自己的记录；具备本项目计划维护范围的人可查看本包送达记录。普通业务用户不能修改已读时间或把失败记录直接改成成功。

本次只启用站内通道，`smsEnabled=false`；站内入库不代表短信送达。短信服务商配置、真实外部通道及通道回执未实现，不能据此宣称外部通知已送达。

## 模板来源和纳入公司库

模板来源日期、政策或制度版本随不可变章节版本保存；未来来源日期拒绝，缺少日期保持未知，不自动填充为今天。送审快照保留来源日期、制度版本和来源模板版本标识，历史版本不被新版本覆盖。

项目自有模板新增“申请纳入公司模板库”，需要新增权限 `buyer:agency:template:promote`，同时仍要求模板维护权限和来源采购包写范围。选择精确项目模板版本、填写公司模板名称、适用性说明、来源日期及政策版本，保存公司模板申请草稿。申请幂等，保留不可变来源版本ID。

申请草稿不能直接被其他项目选用。必须按原 `agency_template_publication` 流程送审，发起人不得自审，通过后才进入可引用的公司模板范围。没有复制项目附件权限，也没有因公司模板发布而开放来源项目的文件访问。

主要代码：[提醒规则](../../backend-java/src/main/java/com/procurement/agency/domain/AgencyReminderRules.java)、[提醒服务](../../backend-java/src/main/java/com/procurement/agency/application/AgencyReminderService.java)、[调度器](../../backend-java/src/main/java/com/procurement/agency/application/AgencyExecutionWorker.java)、[页面](../../apps/tenant-portal/src/features/agency/agency-reminder-panel.tsx)。通知查询通过notification模块自己的应用门面完成，没有从agency跨模块访问通知基础设施。

运行后端导出的 [p2plus-openapi.json](p2plus-openapi.json) 包含37项执行操作、65个关联Schema；在原33项上新增：

| 操作 | 用途 |
| --- | --- |
| GET /packages/{pkg}/reminders | 策略与最近100条送达记录，按权限过滤 |
| PUT /packages/{pkg}/milestones/{id}/reminders | 乐观版本保存节点策略 |
| POST /packages/{pkg}/reminders/{id}/retry | 手动重试失败事件 |
| POST /template-versions/{id}/promote | 项目模板申请纳入公司库 |

以上路径均位于 `/api/v1/buyer/agency/execution` 下。原公司计划模板保存接口增加每节点reminders字段，旧输入未提供时使用原默认策略；原模板版本保存接口增加sourceDate、policyVersion，均保持旧请求兼容。
