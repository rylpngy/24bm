# 专项资金订单清算操作与边界

## 使用范围

本批在已有合同解除、部分履约减量和无独立合同订单清算上，增加专项资金现金归属。限同一项目、当前年度及当前已批准资金方案；必须存在可核验的原付款归属。不得向未知历史付款补造来源，不支持跨年度冻结清算或结项后的重开。

本地功能、云端检查、PR合并和原系统部署分别验收；以本批验收记录为准，不能因文档存在而视为原系统已发布。

## 办理步骤

1. 在订单清算中上传双方协议，核对保留数量、终止数量、清算单价和补偿款。
2. 即使只有一张发票，也须明确填写每张发票/未开票款项的最终货款，不以系统猜测比例代替双方约定。
3. 由供应商真实确认方案，再由采购方提交内部审批；发起人不能自行审批。沿用现有独立 Flowable 清算流程。
4. 审批通过后登记真实退款或补付款凭证，选择发票/款项归属，并填写各专项资金来源金额。来源合计必须等于凭证金额；不自动分摊。
5. 登记最终发票/红冲核对凭证及必要的补偿凭证。非现金凭证不填资金分账。
6. 系统逐票核对实际净款与最终约定，全部一致后完成清算，归档合同和执行资料。后续可按原项目清算规则关闭分包、申请项目终止并释放未用责任。

## 资金及权限规则

- 退款不能超过所选发票在所选来源下的已付净额；不能借另一张发票或另一资金来源的已付款额度。
- 补付不能超过当前项目该来源的剩余责任。多票之间的退款与补付不能仅以合计相抵后直接结清。
- 仍按真实凭证登记，不代表系统自动执行银行付款、退款或税控红冲。
- 原付款流水、原资金分摊、原合同/订单/发票不覆盖。新增清算来源流水以带符号金额补充记录，付款为正、退款为负，与原流水共同计算净付。
- 凭证登记、资金分账和审计在同一事务完成；缺失来源、金额不符、超额、错误归属或重复编号内容冲突时整体失败。
- 清算期间暂停项目普通付款/冲销、未付责任调整，以及涉及来源的额度变更，防止审批依据变化。已清算订单的原付款台账保持只读。
- 登记专项清算须同时具备原清算财务权限和预算查看权限；新建方案还须预算管理权限。订单权限、部门/人员数据范围继续有效。
- 无预算查看权限时不返回内部资金快照或分账；供应商仅查看双方清算业务和凭证，不返回采购方内部资金来源。
- 执行归档保留原现金、清算现金、逐票归属、来源、登记人、完整性摘要和原件。清算后项目终止按实际净付保留责任，不能按原付款金额多占用或多释放。

## 暂未开放

跨年度冻结订单的清算、清算/结项后的受控重开、部分金额冻结更正、新来源引入、历史已付来源重新归属仍需后续独立设计与审批。已付款来源不追溯改写；本批不涉及真实银行或外部财务接口。
