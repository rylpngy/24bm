# 含补偿款清算的受控重开

## 适用范围

在有效项目、未关闭分包中，已完成清算的货款和补偿款可以通过新补充协议重新核定。每版均须供应商确认、独立内部审批、实际收付及最终凭证核验，不修改原协议、原审批、原现金或原归档。

本功能不恢复原实物履约、不增加原采购数量，不替代银行、税务及法务处理。货款与补偿款合计仍不得超过原订单金额；已关闭项目/分包、草案撤销，以及没有明确分项现金归属的历史补偿清算继续拦截。

## 业务操作

1. 在订单清算台账点击“发起补充清算”，上传新的双方协议。系统展示上次约定补偿金额及已付净额，默认带入上次补偿金额，避免无意取消。
2. 分别填写逐票最终货款、清算单价及本次最终补偿款。补偿款不填入货款发票归属金额；首次包含补偿款的清算也须明确逐票货款归属。
3. 供应商重新确认，采购方提交独立审批。原发起人不能替代供应商确认或独立审批人办理。
4. 审批通过后，按“发票或款项归属”分别登记货款或补偿款的退款、补付。不能将货款应退与补偿款应付抵消后只登记净差额。
5. 补偿款全额取消时，登记原补偿款退款，并上传金额为零的补偿结清/取消凭证；缺少凭证不得完成。未曾发生的零金额补偿不要求虚构凭证。
6. 新协议需要重新核验最终货款发票及补偿凭证，不能直接沿用原版本审批或凭证完成。退款不得超过对应款项、年度及原资金来源的实际净付；补付仅可使用当前年度来源。
7. 清算完成后仅最新有效版本进入订单和预算汇总，历史版本和原归档仍可查询下载。撤回或拒绝新申请不会覆盖原已完成清算。

## 资金与历史边界

专项资金下，货款与补偿款均有各自不可变的来源分账。补偿退款只能退其真实原来源，不能借用其他货款来源的余额。历史年度退款仍须明确原责任年度和当前项目方案内的责任回补目标，不自动扩大专项额度。预算默认预警模式不变。

历史记录若未区分货款/补偿款现金归属，或分项净付与上一版清算不一致，页面显示核对原因并禁止自动重开。不得根据总额或名称补造历史归属。

本批不解除“已有订单清算后不能继续跨年度承接”的现有边界；不能把历史补偿款任意迁入新年度。已冻结订单的货款退款与当年补偿收付可以分别核验。

## 隔离验收

使用备份恢复的隔离 API `127.0.0.1:8097`、采购方预览 `127.0.0.1:5201`，不得指向原系统。先使用 `scripts/project-packages-acceptance.mjs` 的既有专项资金参数生成独立 `fundingUi` 场景，再运行：

```sh
ACCEPTANCE_LOCAL_WRITES=1 \
ACCEPTANCE_PASSWORD='<隔离测试账号密码>' \
COMPENSATION_FIXTURE='<基础验收结果JSON路径>' \
ACCEPTANCE_REPORT_PATH='<本批结果JSON路径>' \
node scripts/compensation-settlement-acceptance.mjs
```

脚本验证跨年冻结原款900元后，首次货款600及补偿60元，第二版取消补偿，第三版分别退货款150及补付补偿90，最终净付540元；保留三次供应商确认和独立审批、原始付款及旧ZIP一致性、桌面和移动页面证据。验收原件为测试样本，不代表真实银行收付或税务操作。
