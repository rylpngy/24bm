## 发布顺序

1. 将本批相关代码、V211/V212、OpenAPI及交付文档提交独立PR；不包含客户Word/PPT、数据库备份、密钥或本机验收数据。
2. 完成PR审查和CI检查。已执行的本地回归不替代远程CI结果；未通过时不宣称可以直接上线。
3. 确认发布窗口，重新备份目标数据库及附件存储，保留旧版本静态文件和JAR。不要把本机隔离库或测试文件桶导入目标环境。
4. 从合并提交生成固定构建，在原数据库上仅执行正式迁移，不运行demo seed、不repair迁移历史、不清库。供应商退出必须由管理员配置并发布流程定义。
5. 验证四端登录、采购方权限、资质下载、流程待办及现有订单记录后，再切换入口；检查日志与业务记录。
6. 出现异常先停止写入并保留现场。应用回退与数据库恢复分开决策；不能直接用旧备份覆盖发布后新增数据，不能为了回退删除新表。
