# 采购文件审查：实现与操作说明

本轮关闭独立采购文件审查及发布拦截缺口。它与供应商资格预审是两个不同业务环节，使用底座Flowable，不另建审批运行时。

## 操作顺序

1. 管理员在“流程定义配置”选择“采购文件审查”，设置审批节点、候选角色/人员及条件并发布。至少安排一位独立于发起人的真实办理人，不自动用管理员替代。
2. 采购人员编制招标文件、上传附件、确认时间安排等参数，点击“保存并进入审查”。这一步只保存草稿，不直接发布。
3. 在详情“采购文件审查”提交，填写流程配置要求的自定义字段。尚无已发布流程时提示配置，不默认免审。
4. 审查人从审批中心/流程台账办理，可查看送审正文快照、送审附件、自定义表单及审批历史，并通过业务链接进入招标项目。发起人不能自审。
5. 审查进行中，正文、业务参数及附件不能修改。驳回后可修改重提，原流程和意见保留。
6. 审查通过后可发布。任何文件、附件或相关项目参数变更都会使旧审查不再满足发布条件，须重新审查；前后端都执行发布拦截。
7. 发布后的附件不能直接追加替换。需要正式更正文件的，应采用后续受控澄清/变更方案，不能借普通上传改掉已发布文件。
8. 在业务详情展开“查看送审资料与完整历史”，查看各轮送审快照及人员意见。后补附件不混入旧轮次的送审附件列表。

## 数据及权限

- 每轮生成独立审查编号及Flowable实例，记录版本指纹、发起人、办理人、时间和意见，追加历史，不覆盖旧轮次。
- 审查清单、提交、发布及附件操作仍受租户、角色与数据范围约束。
- 办理岗位还需具备相关招标文件读取权限及对应数据范围；任务分配不会自动扩大整个招标模块或跨部门的数据权限。
- V264仅新增`tender_document_reviews`及索引，不补造历史审批，不追溯拦截已发布项目；旧草稿后续发布须经过新审查。
- 本轮未加入默认审批模板或演示账号到原库，需管理员明确配置实际岗位。
