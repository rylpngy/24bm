## 仍需单独处理的事项

1. 任意评分指标/公式、特殊同分规则等是范围明确后的扩展，不将三维权重描述为全部评审能力。
2. 项目分包各种重采组合、全站每个操作、正式安全测评、生产容量不是本轮样本覆盖的全部范围。
3. 银行实际支付、税控、真实供应链、客户统一认证及财务资产等接口需要第三方条件，不以模拟或站内登记代替。
4. 客户业务口径、岗位授权、基础目录和手机端完整验收仍须真实用户走查。

## 版本及发布原则

统一交付分支为`codex/v1-delivery-unification`，包含此前采购主线收口、文件审查、三维评分及本轮异常处理与契约同步。不包含客户文档、临时数据库和运行密钥。

GitHub PR #155作为统一交付入口，采用普通快进推送补齐内容，不强推、不绕过分支保护。2026-10-31已核实其旧检查未启动原因是账户付款/Actions额度，不是测试执行失败；必须分别记录后续检查、合并和部署的真实结果。

本地部署只在新鲜备份后进行，使用验收同一JAR及本轮构建的四门户；核对原有表数据指纹和附件，保留旧发布目录。不清库、不修复Flyway历史、不触及鲁东环境。发布结果另行追加，不将“代码提交”写成“远端main已合并”或“客户生产已验收”。
