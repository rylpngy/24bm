# 项目执行收口操作指南
## 入口
采购方 → 项目库 → 项目详情 → 执行监控与调整记录 → 展开执行监控。
项目查看/管理、需求查看/创建、询比/招标源业务权限及数据范围分别校验，不因项目管理权限自动获得源业务访问权。

## 需求重新编制
适用于已经关联需求、尚未下发过采购执行的分包。点击“重编”，填写原因：
- 草稿、驳回、已批准需求均退回草稿；原已通过审批不改写、不删除，不作为本次修改的批准凭证。
- 在审需求须由原发起人办理，调用真实工作流撤回；不是原发起人时整个操作回滚，不部分撤回。
- 在需求详情中编辑参数、数量、预算后重新提交审批。页面明确标注历史审批与当前草稿的区别。
- 需要调整分包时，在需求退回草稿/驳回且没有执行的情况下编辑分包；原已批准立项仍然是上限。修改后的需求提交时也重新核验项目部门、年度及分包数量/预算，执行下发再次核对完整性。
- 已下发过采购的分包不能用重编覆盖原执行，即使执行失败，也须按失败重采或终止流程处理。

重编只减少原需求预算占用，不代表学校额度增加、财政拨付或银行退款。重新提交审批时按原预算策略再次核验。

## 受控终止
分包点击“终止”；项目页顶部“终止项目”用于整项目核验：
- 允许尚未采购，或所有有效执行已经流标/废标/取消且没有任何订单的范围。
- 有效采购尚在进行时先在原业务办理流标/废标；存在订单或已结项包时不能一键终止，须在原合同、履约、财务环节处理。
- 原发起人名下在审需求先真实撤回，再取消需求；其他人的在审需求不越权处理。
- 原需求、原执行、审批历史及处理前物料数据保留。调整台账记录人员、时间、原因、处理前快照和本次预算占用减少额。
- 终止分包后批准范围并未自动减少；可重新分包，也可走立项变更减少未执行范围。所有范围取消时，可核验并终止项目。
- 原单执行项目不自动改造或清算；本轮终止扩展面向分包及未采购需求，旧项目存在执行时仍受原边界保护。
- 终止是权限、状态和原因约束下的业务操作，本轮未新建独立终止审批流程；不把“终止”写成另一次审批通过。
- 立项变更审批中，重编、终止和计划调整冻结，既有执行履约仍可继续。

## 节点计划与进度
每包提供需求审批、采购下发、生成订单、收货登记、净付款登记、分包结项六个节点。
点击“计划”，选择节点、日期并填写原因；计划日期须符合节点先后顺序，保存采用分包版本核验，旧版本不能覆盖新设置。
完成状态来源于实际业务，不允许手动勾选为已完成；未完成且超过计划日期才显示逾期，终止包不再计算逾期。
“收货登记完成”不等于质检自动合格，“净付款登记完成”不等于外部银行支付，最终结项仍复用完整履约、质量、对账、合同及付款核验规则。
调整历史采用服务端分页，每页10条，可查看处理前记录。读取源业务失败或缺少权限时提示错误，不展示伪造零金额/已完成状态。

## 整项目档案
已结项或已终止项目可点击“整项目档案”：
- 包含项目状态及批准定义、执行监控、调整历史、实际审批历史、项目/需求/变更等原件台账与原字节。
- 已结项有效执行的归档ZIP原样打包，不用当前页面数据重建历史分包档案。
- 终止项目的包明确标记terminated，不冒称已完成履约；失败执行的引用和处理前数据保留在调整/流程资料中，原采购详细材料仍在源模块追溯。
- 导出重新核验当前源数据权限、归档有效性和附件完整性，任一来源失效即报错，不静默缺包。SHA256SUMS可核验内容。
- 汇总包上限100MB、公共原件最多1000个、调整记录最多1000条；超限按分包和调整台账分页查阅。为保障原数据，不替换/清理任何旧附件。
- 原项目、批准后变更的附件在项目结束后不可改写。已有执行发生后续财务变动导致原档案过期时，应在源业务核验，不假定旧结项仍满足最新条件。

## 保留的部署原则
默认预算warning，不启用强控；原数据和原认证保留。原服务先备份，在独立数据库/对象桶验证迁移，再发布固定构建；禁止把验收库作为原库。
