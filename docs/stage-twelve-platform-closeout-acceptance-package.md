## 已可演示

- 平台后台 3 个核心运营页面：租户列表、企业审核、平台公告。
- 平台运营演示路径：租户列表 -> 企业审核 -> 平台公告 -> 平台看板回看。
- 平台真实动作：停用租户、升级专业版、通过企业审核、发布平台公告、撤回平台公告。
- Java 数据源下的页面稳定性：桌面 1280x720 和移动 390x844 均无加载失败、无 `argument type mismatch`、无 React runtime error、无整页横向溢出。
- 真实点击复验：5 个动作均 `passed=true`，失败项：0。
- 演示讲解辅助：每条运营线都有治理对象、点前检查、点击后反馈、后续流向和运营边界。
- 平台业务边界：平台只维护 SaaS 租户、公共企业准入和平台公告，不直接修改采购方定标、收货、发票和付款状态。

## 仍是入口能力

- 租户列表适合演示租户启停、套餐升级、容量和功能开关口径，但还不是完整套餐计费、用量统计和订阅生命周期中心。
- 企业审核适合演示入驻资料核对、风险确认和审核通过，但还不是完整企业生命周期管理、证照到期提醒和外部风控集成。
- 平台公告适合演示发布、编辑、撤回和运营触达，但还不是完整消息中心、分群推送、触达统计和多渠道通知系统。
- 平台看板可以承接运营总览，但高级平台运营 BI、套餐收入分析和租户健康度评分尚未进入本阶段。
- 公共供应商市场、供应商推荐、品类能力标签和风险预警仍属于后续平台生态能力。

## 暂不做生产化能力

- 不做真实套餐计费、账单、发票和在线支付。
- 不做电子签章、税控开票、保证金、复杂招标、专家评审和竞价轮次。
- 不做完整平台运营 BI、企业风险画像、自动黑名单规则和供应商推荐算法。
- 不做 ERP/OA/财务系统深度集成。
- 不把本阶段平台运营能力包装成完整平台运营后台；本阶段目标是演示闭环而不是生产上线闭环。

## 演示建议

1. 从平台端 `租户列表` 进入，先说明平台方管理的是 SaaS 租户、套餐、容量和功能开关，不参与采购方业务决策。
2. 点击或讲解 `停用租户` 和 `升级专业版`，用顶部反馈和演示闭环面板说明租户治理结果。
3. 进入 `企业审核`，勾选资料确认和风险确认后讲解 `通过企业审核`，强调这是公共企业身份准入。
4. 进入 `平台公告`，演示发布公告和撤回公告，说明公告只做运营触达，不改变采购订单、报价、发票和付款状态。
5. 最后回到平台看板，串联租户、企业审核、公告三类运营数据，说明后续可扩展套餐、用量、市场和运营 BI。
