# 专项资金与项目多来源分摊

## 操作路径

1. 在“预算管理 → 专项资金”新增资金来源，选择管理部门、年度，填写编码和名称。新增来源额度为零，不直接产生可用资金。
2. 点击“额度申请”，填写申请总额度和原因，提交独立审批。流程管理员应先发布“专项资金审批（funding_change）”流程并配置真实办理人。
3. 已批准项目详情展开“项目专项资金分摊”，选择同部门、同年度的已批准资金来源，填写每个来源的金额。合计必须等于项目批准金额；不能超出来源可用额度。
4. 独立审批通过后，项目分摊才生效。付款申请、付款批次仍需按原有流程审批，资金分摊审批不能替代付款审批。
5. 在发票付款金额台账登记实际付款时，明确填写本次付款各来源的金额，合计等于本次实际付款。资金归属和付款流水在同一事务内保存。
6. 冲销付款时，系统按原付款的来源和金额生成完全相反的记录，保留原流水，不重新计算比例、不修改原记录。
7. 项目关闭后，未使用的专项责任释放，已经发生的净付款继续保留来源归属。采购执行档案保留资金审批、项目分摊和付款来源记录。

## 控制规则

- 年度额度及项目分摊均支持撤回、驳回和审批历史查询；审批时重新检查额度、项目版本和原分摊版本。
- 发起人与审批人分离，沿用统一工作流权限、部门数据范围、任务历史和审计。
- 台账及审批记录分页查询，不截断为固定条数。
- 项目已有任何付款历史后，普通分摊编辑不允许追溯启用、重新分摊或撤销分摊；即使付款后来冲销，也不清除历史限制。跨年仅通过专用承接审批继承未付责任，不改历史付款来源。
- 专项资金跨年通过项目承接审批明确选择目标来源，操作见 special-funding-carryover-guide.md；只承接未付责任，历史净付保留原年度及来源。立项变更和订单清算仍不直接开放；尚无付款且未发生跨年承接时，可先独立审批撤销分摊。
- 未启用专项资金的项目、历史付款和部门预算预警模式保持原有行为；本次迁移不为历史单据补造来源归属，不初始化资金数据。

## 尚未覆盖

后续批次已补专项冻结付款整笔更正与当年责任回补，见 funded-frozen-correction-guide.md；付款后仅在当前项目既有来源间调整未付责任，见 funding-unpaid-reallocation-guide.md，不能改写原已付归属。已履约结清项目的终止与未用责任释放见 special-fund-project-liquidation-guide.md。新来源引入、历史已付重新归属、专项订单退款/补付来源分账及清算重开仍未覆盖。第三方财务实际出款、客户统一身份认证和客户环境容量验收仍依赖外部环境。以上按各批本地验收、CI、合并和部署状态分别记录，不代表原系统已发布。
