## 修复说明

审批完成接口返回后，旧实现立即关闭弹窗，但异步刷新尚未完成。快速办理下一节点会重新选中旧任务，页面提示“流程节点已变化”，使连续办理受阻。

改为刷新待办完成后再关闭弹窗，并在刷新期间禁用提交、取消和关闭，显示“刷新待办中”。新增回归测试先确认旧代码失败，再验证修复；同一浏览器连续两级审批真实场景通过。后端旧任务校验保持不变，不绕过权限或流程状态。

## 下一批实施顺序

1. **发布收尾**：PR111已完成受控合并、原库副本验证、备份与固定构建发布。下一项单独交付本轮刷新修复5fe7dd42，按其自身CI和审查结果推进，不混入已确认的PR111版本。
2. **绩效评价周期与整改闭环**：先实现周期、指标权重、分配评价人、提交汇总、人工确认评级、整改任务及复核。保留现有手工评价，不自动淘汰或加入黑名单。验收重点为一次完整评价到整改关闭，以及租户和评价权限隔离。
3. **供应商岗位及权限配置**：在既有标准角色基础上增加受控自定义角色，限制可授权范围，支持成员多角色和审计；身份平台同步另行定义。验收覆盖只读、业务办理、管理员，以及前后端一致的越权拒绝。
4. **退出清理范围扩展**：按现有合同、售后及应付数据能力补齐阻塞项与责任人处理，不用票面金额冒充剩余应付；先逐笔展示，再接入退出前后端统一校验。数据口径未建立的项明确显示不可判定，不能直接允许退出。
