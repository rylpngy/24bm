# 跨年度承接与已有订单终止清算

## 办理入口

采购方企业端 → 项目库 → 项目详情 → “跨年度承接与终止清算” → 展开办理台账。
办理人员须具备项目管理权限；查看完整核验依据还需相应需求、采购执行、合同、发票及审批查看权限。
审批在统一审批台账中办理，发起人与审批人必须是不同账号。可在流程定义配置中分别发布“跨年度承接”和“项目终止清算”的流程与动态表单。

## 跨年度承接

1. 核对立项年度、当前责任年度、预算占用及阻断原因。
2. 选择晚于当前责任年度且不早于本年度的承接年度，填写原因，完成已发布审批表单后提交。
3. 原年度占用在审批期间不变；同项目不得重复申请，也不能新增分包、需求和采购执行。
4. 独立审批通过后，原责任年度的尚未付款占用转入目标年度。项目立项年度、需求及订单原始时间、原批准明细不改写；也不修改或转移任何年度预算额度。
5. 预警模式下记录超额预警并允许承接；非预警模式下若目标年度额度不足，审批事务整体回滚，需先审批调整年度额度。
6. 驳回、发起人撤回、资料变化和重复请求均不转移预算；申请及审批历史保留。承接至未来年度后，不提前生成属于未来年度的新需求。

### 当前边界

- 支持未付款及已有可核验付款的项目：已支付责任留在原责任年度，未支付责任转入新年度；支持连续多次承接，见project-paid-carryover-guide.md。
- 付款流水、状态不一致、跨项目混合需求或预算归属不一致时明确拦截，不自动把已支出资金挪到新年度。
- 这是采购预算责任的年度分摊，不改写付款交易日期或银行账，不替代财务会计系统；跨年退款、已冻结支出更正及专项资金分账仍待开发。

## 已有订单终止清算

1. 先在原履约模块完成订单确认、收发货、验收、合同、发票、付款审批与实际金额登记。
2. 已执行分包先办理结项和执行归档；未采购分包先办理原无订单终止。未纳入已结清执行的需求必须先处理。
3. 进入清算申请。系统核验原执行的合同、履约、三单匹配、净付款、未结事项和预算归属；问题逐条显示，不允许直接“清零”。
4. 填写终止原因，提交独立审批。审批时再次锁定订单核对，资料发生变化须驳回重提。
5. 批准后项目标为“已终止”，不是“全部履约完成”。原合同、订单、收货、发票、付款及原分包档案保留；原订单金额、数量不被改小。
6. 整项目档案新增承接清算台账与对应审批历史，并复用原分包 ZIP。已清算项目的付款登记及冲销被拦截，避免事后改写清算依据。

### 当前边界

- 本轮支持已履约、已结清订单后的剩余项目计划终止。
- 未发货订单取消、部分履约减量、实物退回与退款、红字发票及合同解约补偿的专项清算仍未完成；系统会明确阻止未结事项进入清算。
- 售后记录不等于实物已退或银行退款完成；付款登记不等于真实支付通道。没有证据的情况不会显示为已结清。

## 数据保护

V238新增业务台账；V239扩展已支付责任分摊视图，不改写旧记录、不修改旧迁移、不导入验收数据、不切换预算模式。原数据先备份，在隔离数据库完成迁移与业务验收后再发布。
