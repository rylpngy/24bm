# 已付款项目跨年度预算责任分摊

## 入口与办理

采购方 → 项目库 → 项目详情 → 跨年度承接与终止清算 → 展开办理台账。
页面同时展示累计预算责任、已核实净付款、拟承接未支付责任，以及逐年责任分摊。

1. 核对项目、订单、发票、真实付款登记流水和凭据编号；金额未知或付款状态不一致时须先核对，不能把缺失资料当成零付款。
2. 选择承接年度并填写原因，补充已发布审批流程的动态表单，提交独立审批。发起人不能自审。
3. 审批期间原年度数据不变化。办理时再次锁定订单并核验资料；金额、付款编号或凭据变化后须驳回/撤回重提。
4. 批准后，原年度的已支付责任保持原年，只有未支付责任进入目标年度。年度预算额度、项目立项年度、订单金额、原始日期和付款交易日期均不改写。
5. 新付款按当前已批准的预算责任年度归集；当前年度尚未纳入承接审批的付款，可按原有权限、合同和付款审批规则更正。已被承接审批冻结的付款不可直接冲销。
6. 支持再次承接：只冻结当前责任年度新增的净支付金额，不重复冻结之前年度已支付金额。
7. 分包及项目结项继续核验原合同、履约、发票和全部净付款。根档案增加“预算年度分摊.json”，保留原付款凭据、承接审批台账和原分包ZIP。

## 金额示例

- 批准需求预算1200，采购订单900。第一责任年度先登记300，承接后原年保留300，新年度责任900（含尚未最终释放的300预算结余）。
- 新年度登记200，若按原有规则冲销该笔未冻结登记，则该年度净付款归零，之前年度300不变。重新核实登记200后，再次承接。
- 第二次承接后，两个历史年度分别保留300和200，最新年度责任700。最后在最新年度登记400，订单累计净付款900。
- 履约、发票及付款全部核验结项后，最终责任分别为300、200、400，合计900；300结余在当前责任年度释放，不重复计算订单或支出。

## 控制与边界

- 默认保持原预算预警模式。非预警模式下只校验承接目标年度的责任余额，额度不足时整个审批回滚；原年度已支付责任不挪到目标年度，也不要求用目标额度重新覆盖历史支出。
- 一笔项目只允许一笔承接/清算在审；保留防重复、版本、数据范围、办理人及审计检查。
- 本功能是采购预算责任归集，不是银行支付、财务凭证过账或会计年度重述；实际支付日期和财务系统记录保持原样。
- 跨年退款、冻结支出更正、会计凭证调整及专项资金分账仍未实现；不提供绕过审批直接修改历史分摊的入口。
- 升级前已在审的旧版承接申请若缺少新版付款依据，审批时会提示资料变化，应撤回/驳回后重提；不会自动迁移为“已通过”。

## 数据保护

V239只替换年度责任分摊视图，兼容V238已批准且净付款为零的历史申请，不修改旧迁移、旧快照、预算模式或原业务记录。发布前备份并以隔离恢复演练、固定产物验收和逐表原行摘要核验为门禁。
