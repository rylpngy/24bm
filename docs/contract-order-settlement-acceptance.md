# 合同撤销、解除、部分履约减量与退款清算

## 业务范围

- 合同草案撤销：双方确认未实际履行、无发票和付款责任后，经独立 Flowable 审批撤销并清算。
- 合同解除：保留原合同、原订单及历史履约记录，通过清算协议明确最终价款。
- 部分履约减量：保留已合格验收数量，仅终止未履行数量；可在协议范围内约定不高于原单价的清算单价。
- 退款与补付：按约定净额登记实际退款或补付款凭证，附真实原件、凭证编号、金额、登记人及时间。
- 财务调账：保留原始票面额、付款流水及冲销记录，不修改历史金额；以最终发票/红冲核对、补偿款凭证和清算台账展示结算结果。

## 办理入口

1. 采购方“采购订单 → 详情 → 合同解除与订单清算”核对原始行项，上传协议并提出方案。
2. 供应商“销售订单 → 详情”下载共享协议并同意或拒绝。未共享的内部附件不提供供应商下载。
3. 原发起人提交内部审批；管理员可在流程定义中配置“合同解除与订单清算”的办理人、候选角色和条件。
4. 独立审批人在统一审批中心核对业务快照与附件；审批通过不代表实际退款完成。
5. 采购方登记清算凭证，净付款与约定总额相等且财务凭证齐全后，完成清算并归档合同。
6. 采购执行及项目分包通过原有结项入口归档；预算结余只在证据完整并完成采购归档后释放。

## 安全与一致性

- 按租户、数据范围、订单归属和供应商账号校验；发起人与供应商确认人不能相同，内部审批不得由发起人办理。
- 两端订单接口只输出清算所需行明细和摘要，不因拥有订单查看权限而暴露原始合同、发票或银行流水整行数据。完整依据仍保留于受权审批与审计档案。
- 使用预算锁、订单锁、版本号及请求编号防止重复确认、重复凭证、重复回补库存。
- 清算期间禁止继续发货、收货、修改合同、原始发票或付款责任；拒绝和审批驳回恢复原状态。
- 凭证校验原件大小及 SHA-256，清算协议保留不可变副本；归档 ZIP 包含清算记录、审批历史及相关原件。
- 库存只恢复可证明已扣除且未发货的预留量，历史库存依据未知时不推算，未跟踪库存不回补。
- 保留预算预警模式，不改变既有租户配置，不向原系统导入验收样例。

## 明确边界

- 在途货物、待验收或不合格货物需先完成实物责任处理，不将“终止”冒充退货或验收。
- 已冻结的跨年度历史支出、历史付款未知、多发票分摊、超原订单额补偿不自动推算，明确阻断并提示核验。
- 退款、补付款和红冲为人工核实后的凭证登记，不宣称已接通银行资金划转或税控系统。
