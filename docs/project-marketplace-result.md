# 商城与竞价项目分包贯通验收说明

日期：2026-10-25。基线：`main@4ba948fd77411ed8f77e6690029d397d0af7b4b5`。

## 已实现

商城分包通过已批准需求的完整物料集合选型，逐项核验SKU关联物料、单位和数量，支持同一物料多个SKU。同包同供应商，跨供应商通过拆包处理。目录可见性、上架状态、库存、起订步长、企业采购控制和到货承诺继续生效。服务端成交价不能超过需求及分包批准额。

商城生成原需求关联的真实采购来源及订单，不重复生成需求或独立预算占用；提交编号和内容校验、项目锁、库存锁及事务回滚共同防止重复下单。品牌/型号/参数/价量、原批准包与需求集、办理依据及人员时间保存为成交快照，并进入项目档案，后续商品修改不覆盖快照。

竞价包下发真正的竞价草稿，支持起拍价、降价步长、起止时间、自动顺延窗口和时长；沿用真实供应商报价、再次降价、截标、定标审批、订单履约链。原单个有效执行、失败无订单重采、立项变更在审冻结、项目与源业务权限和数据范围保持有效。

## 已执行的验收

- 24项项目数据库集成专项通过，包含商城预算归属、原样重试、库存只扣一次、改内容重复提交阻断、错误价量/单位/物料回滚、审批和源权限校验、多SKU/混合供应商边界、两个并发提交只生成一个订单、成交快照不随目录修改、竞价草稿及批准额上限。
- 前端658项测试、项目界面23项专项、7项运维测试通过；接口快照同步及测试日期检查通过。包括多层弹窗只响应最上层Esc、下单忙碌期间禁止退出和失败保留原提交编号。
- 隔离HTTP实际完成14组检查。询比、招标、失败重采、竞价、商城五包共6000元需求预算，4500元净付款登记，1500元结余释放；汇总、预算和归档无重复。
- 竞价以实际报价验证超起拍价和反向加价被拒绝；供应商真实降价后等待实际截止时间再开报价，不改库时钟、不使用提前开报价冒充截标成功。
- 商城真实下单、原样重复提交、换编号重复购买阻断、源预算与成交快照查询通过；五包都完成合同审批、供应商确认、发货、逐行收货、发票、付款审批和登记、结项归档。

最终固定提交的完整云端CI、重复HTTP验收、浏览器及ZIP核验、合并与原系统部署，以发布目录RESTORATION.md、CI回执、构建哈希和前后数据核验为准。本说明不代替尚未执行的最终发布动作。
