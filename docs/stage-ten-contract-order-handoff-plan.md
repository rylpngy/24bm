# 阶段十计划：合同管理承接订单

## 阶段定位

阶段十不是从零开发合同系统，而是在阶段九可演示版本之后，复用阶段五合同管理能力，把合同管理重新纳入当前“产品可演示优先”的主线。

阶段五已经具备大量合同基础能力：合同台账、订单生成合同、合同保存、合同审批、附件元数据、履约事件、归档门禁、合同与收货/发票/付款的只读聚合和复核辅助。阶段十的第一目标不是继续堆更多合同细节，而是把这些能力收束成一条现场可讲、可点、可验收的“订单生成合同 → 合同审批 → 合同履约事件 → 合同与订单/发票/付款关系”链路。

阶段十第一轮必须明确边界：

- 复用阶段五合同管理能力，不重新设计合同对象。
- 承接阶段九可演示版本，不破坏采购方、供应商、平台端 17 个真实动作。
- 聚焦订单生成合同、合同审批、合同履约事件、合同与订单/发票/付款关系。
- 不做电子签章，不接外部合同系统，不做法务红线和合同版本对比。
- 不并行启动商城直采、竞价采购、招标或 AI。

## 第一轮 MVP

阶段十第一轮 MVP 建议只做“合同承接订单演示路径复核与轻量补强”。

必做：

1. 复核采购方合同管理入口是否仍在采购订单之后、收货验收之前。
2. 复核合同台账是否能读取 Java 合同数据，并展示合同编号、供应商、金额、状态、关联订单和履约进度。
3. 复核从采购订单生成合同草案的入口是否清晰，避免演示者不知道合同从哪里来。
4. 复核合同审批入口是否能讲清：提交合同审批、审批中心处理、审批通过后合同生效。
5. 复核合同履约事件是否能承接收货和付款动作，形成合同视角的履约证据。
6. 复核合同详情是否能讲清合同与订单/发票/付款关系。
7. 输出阶段十合同演示路径文档和必要测试。

第一轮暂不做：

- 电子签章、真实盖章流、法务审查。
- 外部合同系统、ERP、OA 或财务系统集成。
- 合同模板库、条款结构化、红线批注、版本对比。
- 复杂履约状态机、自动违约预警、定时扫描。
- 独立合同付款计划写入接口和真实支付。

## 主流程草案

推荐阶段十演示顺序：

1. 采购订单：说明订单从询价比价定标生成，是合同草案的业务来源。
2. 合同管理：从订单生成合同草案或选择已有合同。
3. 合同审批：提交合同审批，审批中心处理合同审批任务。
4. 合同生效：审批通过后合同进入生效或履约状态。
5. 合同履约事件：从合同联动入口进入收货验收或发票付款，沉淀履约事件。
6. 合同与订单/发票/付款关系：在合同详情回看订单状态、收货状态、发票金额、付款状态和归档门禁。

这条路径只说明平台内合同协同状态，不声明电子签章、外部合同归档或真实资金划拨完成。

## 验收口径

阶段十第一轮可以声明：

- 合同管理将作为阶段九之后的第一条后续业务主线。
- 阶段十会复用阶段五已有合同能力，不从零重做合同模块。
- 第一轮重点是合同承接采购订单，并讲清合同审批、履约事件和订单/发票/付款关系。
- 电子签章、法务审查、外部合同系统和真实支付仍不进入本轮。

阶段十第一轮不能声明：

- 合同全生命周期已经生产级完成。
- 合同附件已经真实上传到对象存储。
- 合同签署、法务审查、印章和外部归档已经完成。
- 合同可以自动驱动订单、收货、发票或付款状态。

## 暂缓范围

以下方向继续暂缓，不在阶段十第一轮并行启动：

- 商城直采：等协议价商品、供应商商品目录和快速下单需求明确后再启动。
- 竞价采购：等轮次、排名、截标、公平性规则明确后再启动。
- 招标：等专家评审、保证金、招标文件、开标评标合规需求明确后再启动。
- AI：等采购、报价、履约和供应商绩效数据沉淀足够后再启动。
- 真实支付和银企直连：等财务接口、幂等、审计、回滚和异常恢复方案明确后再启动。

## 下一轮建议

下一轮建议：补阶段十合同演示路径复核。

具体做法：

1. 打开 Java 模式采购方合同管理页，确认合同台账、合同保存、合同审批、合同履约和合同财务摘要能稳定展示。
2. 固化阶段十合同演示路径，覆盖采购订单、合同管理、审批中心、收货验收、发票付款。
3. 如果现有页面缺少阶段九式演示提示，再补“合同演示总线”和推荐合同样本。
4. 继续保留阶段九的验收纪律：每轮都要有证据文件、测试和暂不声明范围。
